② EOG tail sync 拆解：是真實 GPU 計算，不是 overhead

08-19 只量到「EOG sync ~4ms」的黑箱。今天用 CGC_TAIL_DBG（segmented loop 後立刻 ggml_backend_synchronize）+ CGC_METAL_DBG（get_tensor_async/synchronize）把 4.4ms 拆開。

EOG 4.4ms 組成CGC_TAIL 4390-4852us / CGC-SYNC wait_last 3569-4480us
~4.4ms GPU tail 執行
<0.1 blit
  • 為什麼 CPU 要等 4.4ms：llama_get_sampled_token_ith 第一行 ctx->synchronize() 等最後的 logits blit command buffer（CGC-GST 證實 caller 側 4.8ms / callee 側 1us 的差異全在 synchronize）。
  • 這 4.4ms 是「最後幾層 + output layer」的 GPU 執行：segmented dispatch 只等每個 top-k 分段，tail segment（末段純計算）沒有被等，等到 getter 才補付。
  • 單流貪婪解碼下結構性無法省：logits 是整個圖的最後產出，CPU 必須等它；把 wait 提前（graph_compute 內同步）只是把 34.2+4.4 搬到 decode 帳上，總 wall 不變。生產版（08-19）同樣付這 4ms。
  • 突破的唯一途徑 = MTP：draft token 讓 step N+1 的早期層與 step N 的 tail 重疊，把這 4.4ms 藏進下一個 step 的 GPU 計算。

③ Segmented pipeline 健康度（CGC-SEG）

CGC_OA_ASYNC segmented dispatch 的逐段成本：submit 下一段 → wait 當前段 → hook 寫 remap。

計量值說明
segment wait955 → 1277 µs/段等 seg[i] 主 cmd buffer 完成；隨暖機（expert cache）略降
submit 下一段104 → 140 µs/段與 GPU 執行重疊，不佔 critical path
topk hook callback~4-5 µs/段CPU 寫 remap leaf，極輕量

結論：管線是滿的——wait≈GPU 每段執行時間（~1ms），submit 140µs 被前一段執行蓋掉，hook 5µs 可忽略。40 段 × ~1ms ≈ 34ms 就是 compute 本體，沒有 pipeline 空轉可撿。
