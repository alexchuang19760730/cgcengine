## 0. 一句話

`SHAPE_ROOFLINE_2026-09-22.md` §7 在 kernel 層證明**每個 draft token 都是全額再讀一次自己的
expert**（n=1..4 per-token 成本差 +4.6% / −3.7%），所以 verify 的成本律是**對 token 數嚴格仿射、
沒有批量折扣**。把它接進預算之後：

1. **維度越寬，要求的 accept 越高**（k=1 只要 0.553，k=3 要 0.731，k=7 要 0.851）。
2. **今天的最佳 k 是 1，不是 3**：用同 harness 實測比值反解出的 `α=0.654`，
   `k=1` 給 **11.42 t/s = 1.066×** 基線 —— 而 `k=3` 是 0.889×（淨虧）。
   **這是純配置改動，不動一行引擎。**
3. **accept 軸單獨到不了 25**：完美 drafter 的天花板是 **19.39 t/s**。
   要 25 需要 `c_tok ≤ 40 ms`（−22%）；**把整個 kernel 項拿掉也只到 23.15**。
   真正的靶是那 **43.20 ms/token 的非 kernel 成本**。

## 1. 成本律

```
cost(T) = 41.74 + 51.56 * T  ms      T = verify 批次的 token 數 = k + 1
```

由**兩個實測點**定出：

| 點 | 值 | 來源 |
|---|---|---|
| T=1（MTP off） | 93.3 ms | `S0_MTP_ONOFF_AB_2026-09-21.md`，OFF 臂中位（9 筆落在 10.6–11.3 t/s） |
| T=4（MTP on k=3） | 247.98 ms | `TARGET25_TWO_AXIS_2026-09-20.md`，CGC-DECPROF，log `20260920_023021` |

⇒ `c_tok = (247.98 − 93.3)/3 = 51.56 ms`（落在引擎側量的 46–59 ms 帶內），`C_fixed = 41.74 ms`。

**內部分項**：`c_tok = 8.36（實測 MoE GEMV，16.2%）+ 43.20（其餘 83.8%）`。
這與 §7 的「kernel 只解釋 15–19%」互相印證。

### ⚠️ 這個擬合的誠實邊界（不可省略）

* **2 點 2 參數，零自由度** ⇒ 它**描述**資料，不**檢驗**資料。`k>3` 的外推沒有依據。
* 支持「仿射**形式**」的不是這 7 行算術，而是**獨立的 kernel 量測**（n=1..4 線性且截距≈0）
  與 `k=0` 能精確回推出 `S0`。
* **兩個點來自不同 harness**（llama-bench vs server）與不同 profile（prod25 vs prefill250）。
  這是這個擬合最弱的一環。
* 檢驗方法：**補一個 T=2 或 T=3 的臂**（第三點），那是唯一能證偽線性性的實驗。

## 2. 損益平衡：維度越寬，要求的 accept 越高

`E(k)` 用幾何接受模型 `E = 1 + Σ_{i=1..k} α^i`。要贏過一次普通 step，需要 `E(k) > cost(k)/S0`：

| k | T | cost ms | 需要 E | **需要 α** |
|---|---|---|---|---|
| 1 | 2 | 144.86 | 1.553 | **0.553** |
| 2 | 3 | 196.42 | 2.105 | **0.664** |
| 3 | 4 | 247.98 | 2.658 | **0.731** |
| 4 | 5 | 299.54 | 3.211 | **0.776** |
| 5 | 6 | 351.10 | 3.763 | **0.808** |
| 6 | 7 | 402.66 | 4.316 | 0.833 |
| 7 | 8 | 454.22 | 4.868 | 0.851 |

**這就是「k_eff 的經濟學變了」的具體形式**：過去假設批次會攤薄，所以寬 k 只受 accept 飽和限制；
現在成本嚴格線性，所以**寬 k 變成一個「賠率變差」的賭注** —— 每多一個 draft token 都要付全額，
而它被接受的機率是 `α^(k+1)`。

## 4. 今天的 α 是多少：用**同 harness** 的比值反解

跨 harness 的兩個點有誤差，但 `S0_MTP_ONOFF_AB` 那輪的 ON/OFF 是**同一個 harness、同一個 shape、
只差 `--spec-type`**，所以它的比值不帶跨 harness 誤差。把 `0.889 @ k=3` 反解：

```
measured ON/OFF = 0.889 at k=3  => per-draft accept alpha = 0.654
break-even alpha at k=3         = 0.731   => k=3 今天是 NET LOSS
at alpha = 0.654 the best k     = 1:  11.42 t/s = 1.066x baseline
    k=1  11.42 t/s  1.066x   <- best
    k=2  10.60 t/s  0.989x
    k=3   9.53 t/s  0.889x   (by construction == the measured ratio)
    k=4   8.50 t/s  0.793x
```

### ⇒ 可證偽的預測

**把 `--spec-draft-n-max` 從 3 改成 1，MTP 應從 −11%（0.889×）變成 +6.6%（1.066×）。**
這是**純配置**改動（`run_server.sh` 的 `CGC_SERVER_MTP_N_MAX`），不動引擎、不碰 bit-identity。
⚠️ 反解的 `α=0.654` 來自 3 組配對、其中 2 組熱標 HEAVY，原作者已標「比值只可定性讀」
⇒ **預測的方向可以引用，數值不要當量測**。

## 5. accept 軸的天花板，與真正的靶

```
α=1（完美 drafter）、k→∞ : 19.39 t/s = 1.81x 基線
25 t/s 需要 c_tok <= 40.00 ms  ⇒ 每 token 成本要砍 22%
把**整個** kernel 項拿掉   : 41.74 + 43.20*T ⇒ α=1 天花板 23.15 t/s
```

* **accept 單獨救不了 25**（19.39 的上限）。這與 `POOL_BUDGET_COST_DECOMP` 的
  「`a → 1` 在 `m=0.474` 下只有 1.85×」是同一結論，但現在成本律是實測拟出來的。
* **kernel 全拿掉也只有 23.15** ⇒ kernel 是必要條件，不是充分條件。
* **真正的靶是 `c_tok` 裡的 43.20 ms/token 非 kernel 成本**（in situ 有效頻寬 ~12 GB/s vs
  實測峰值 100.5 GB/s，見 `SHAPE_ROOFLINE` §5/§6）。
