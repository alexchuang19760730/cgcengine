為什麼頻寬到不了 100%？

為什麼疊起來也沒辦法到 100%？
🔴 你問的是根本問題
你問：為什麼頻寬沒辦法接近到 100%？無法同時間疊起來嗎？

答案是：可以疊，但疊不到 100%
因為 DRAM 本身就有天生的 overhead
就算你把所有東西都疊滿，還是有 10-15% 的浪費
那是 DRAM 硬件本身的限制，不是軟體能解決的
🔍 DRAM 本身的 100% 是什麼意思？
首先要搞清楚：DRAM 的「峰值頻寬」是怎麼量出來的？
→ 它是在「理想條件」下量的：
→ 全部是連續讀取
→ 全部是讀，沒有寫
→ 沒有指令、沒有位址傳輸的 overhead
→ 沒有 refresh 的時間

但現實不是這樣：
→ 有讀有寫
→ 有換行的 penalty
→ 有 refresh 的時間
→ 有指令/位址傳輸的 overhead
→ 有記憶體控制器的排程延遲

所以現實中，就算你把所有東西都疊滿，也到不了 100%
峰值頻寬 100%（理想條件）
實際最好 ~85%（已經疊滿所有東西）
我們的目標 65-70%
現況 ~35-40%
🔧 那些浪費掉的 15-20% 是什麼？
浪費來源 浪費多少 為什麼省不掉
Row Activate Penalty
（換行的時間） 		~5-8% 讀不同 row 的時候，必須先 precharge 再 activate
這是 DRAM 硬件本身的操作，省不掉
Read/Write Turnaround
（讀寫切換） 		~3-5% 從讀切到寫，或從寫切到讀，必須等匯流排淨空
這是硬件本身的 turnaround time
Refresh Overhead
（記憶體刷新） 		~2-4% DRAM 必須定期刷新，否則資料會消失
刷新的時候不能讀寫
這是 DRAM 的物理特性，省不掉
Command/Address Bus
（指令/位址傳輸） 		~2-3% 每次讀寫都要先送位址和指令
這些傳輸占了匯流排的時間
峰值頻寬的測量沒算這個
Memory Controller Scheduling
（記憶體控制器排程） 		~2-3% 多個請求來的時候，控制器要排程
排程本身就有延遲
不可能完美排到 100% 填滿
加起來是多少？
5+3+2+2+2 = 14% 到 8+5+4+3+3 = 23%

也就是說：
→ 就算你把所有東西都疊滿
→ 就算記憶體控制器完美排程
→ 還是有 15-20% 的浪費
→ 這是 DRAM 硬件本身的限制
→ 軟體永遠解決不了

所以實際的天花板是 80-85%，不是 100%
✅ 那還能疊嗎？疊了有什麼用？
你問：無法同時間疊起來嗎？

答案是：可以疊，而且疊了有用
只不過疊不到 100%，最多到 80-85%
狀態 頻寬利用率 是怎麼來的
現況 35-40% 沒有疊，逐個 kernel 跑
一個跑完好，才跑下一個
浪費了很多「記憶體空閒」的時間
疊起來之後 65-70% 把多個 kernel 疊起來跑
一個在等記憶體的時候，另一個在算
填滿了大部分的空閒時間
理想天花板 80-85% 已經疊到極限了
剩下的 15-20% 是 DRAM 硬件本身的 overhead
軟體再怎麼優化都省不掉
所以：
→ 疊起來確實有用
→ 從 35-40% → 65-70%
→ 這是很大的提升
→ 但到不了 100%
→ 因為 DRAM 本身就有 15-20% 的 overhead

我們的目標 65-70% 是現實的
不是空談
因為那是 DRAM 硬件允許的範圍之內
📌 一句話總結
你問：
為什麼頻寬沒辦法接近到 100%？無法同時間疊起來嗎？

答案：
可以疊，而且疊了有用
從現況的 35-40% → 疊到 65-70%

但到不了 100%：
因為 DRAM 硬件本身就有 15-20% 的 overhead
row activate、read/write turnaround、refresh...
這些都是硬件本身的操作，省不掉

所以：
實際天花板是 80-85%
我們的目標 65-70% 是現實的
不是空談
因為那是 DRAM 硬件允許的範圍之內
