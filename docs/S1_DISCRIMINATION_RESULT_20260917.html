結論：上一步的「未裁決矛盾」已經解除，而且兩個候選都否掉了。 兩臂真的不是 bit-identical；分歧需要 GPU 算出的 slot 向量被真正消費才會出現， 而 ids 本身逐層是對的、S1 多出來的四個節點可證惰性 ⇒ 剩下的是排序／狀態 （同一組 ids 讀到不同的池內容），與分梯看到的 UNSTABLE 形狀一致。

p25-keepleaf ＝ S1 的四個額外節點全部照建（per-layer table／CONT／GET_ROWS／VIEW）， 但 mul_mat_id 仍吃 host leaf。r12（ARMS="p25-gputime,p25-keepleaf"、 HASH=1、10 名、兩輪）：

p25-keepleaf 與錨逐位元相同（md5 ＋ 每一個捕獲張量） ⇒ 那些額外節點是可證惰性的，而分歧需要 GPU 算出的 slot 向量被真正消費。

候選的處置

候選處置依據
slot 對映指到錯的專家排除repo 的 POST 逐層讀回已證 gather == host mapping at every layer（ids 是對的）
擷取讀到錯的位置排除同一支儀器對 keepleaf 報出逐位元相同、對 slotgpu 報出穩定的差異， 而該差異有獨立量測（answer_md5_set）佐證 ⇒ 不是憑空製造差異
額外節點擾動圖／排程佈局排除keepleaf 建了全部節點卻與錨逐位元相同；且 repo 記「all 39 layers' nodes are bit-identical」
排序／狀態剩下S1 多了一條 table 依賴，改變了「remap 算好」與「池內容被讀」之間的時序 ⇒ 同一組 ids 讀到不同的權重
⇒ S1 的真缺陷是「排序／狀態」，不是錯誤對映，也不是儀器。 這與分梯看到的 UNSTABLE 形狀（不是穩定地錯）完全一致 ——原檔也已經指出：「the full arm is not stably wrong but UNSTABLE, which rules out a plain deterministic mapping error and points at ordering/state」。 §9.18.4（「載體是池／slot 的權重內容」）因此以「race」的形式復活， 而不是以「對映錯了」的形式。

3. 這個結果對既有路線的意義

  • M1 的閘門前提交好了：M1 改的是 gather 順序，而現在知道分歧住在 「remap 與池內容的時序」上 ⇒ CGC_S1_KEEP_LEAF 與 p25-slotgpu-l20 這兩個既有臂，可以直接當成「時序是否被動到」的哨兵（前者應永遠等於錨，後者應永遠等於錨）。
  • 下一步的正確問法不再是「哪一層」（分梯已證明那條路只有一個自由度）， 而是「哪一段時序」：把 publish_slot_table 與 remap 節點的相對位置當成自變數， 用 keepleaf（惰性）與 l20（門檻外）當兩端錨。
  • 不要再加同形狀的分梯（原檔明講）。
