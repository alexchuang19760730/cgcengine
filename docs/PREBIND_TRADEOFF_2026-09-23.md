## 1. 你的 33%：方向對，但有兩個更正

### 1.1 更正一：門檻事件比 `0.87^8` 嚴 —— 指數是 15.5 不是 8

快路徑的條件是「真 ids 全部 resident」，而真 ids 的規模是**整層 union**，
實測 `U = 15.5` 個專家/層（ntok=4），不是 8 個。

```
0.87^8   = 32.8%    <- 你算的
0.87^15.5 = 11.6%   <- 真正的門檻（若 expert 獨立）
```

⇒ 你的「命中率是關鍵」比你自己估的還關鍵。

### 1.2 ★★ 更正二：但我第一版把這個門檻用錯了，方向是錯的

我第一版寫 `f_clean = q^U`，其中 q = 預測覆蓋率。**這是錯的。**

基線已經有 85% 的被選專家常駐（`llama-context.cpp:5380` "15% of selected experts are
non-resident"）。預指派**不是**從零建立常駐，它只是把那 15% 冷的救回來：

```
r(q) = p_res0 + (1 - p_res0) * q          # 該專家在 hook 時已 resident 的機率
     = 0.85 + 0.15 * q
f_clean = r^U
```

| q | 錯的 `q^15.5` | 對的 `r^15.5` | Δt/s（對的） |
|---|---|---|---|
| 0.52 | 0.02% | **31.1%** | **+5.4%** |
| 0.87 | 11.6% | **73.7%** | **+17.2%** |
| 0.91 | 24.5% | **81.0%** | **+19.5%** |
| 1.00 | 100% | 100% | +25.8% |

**我第一版說「q=0.87 只得 +0.8%，等於沒做」—— 錯的，是 +17%。**
誤差來源是我把「被預測覆蓋」當成「resident」的唯一路徑，忘了基線那 85%。
（錯誤方向是保守的：它會讓我們放棄一個值得做的東西。已修，selftest 第 3 項專門釘住
`q=0 => f_clean == p_res0^U`。）

⇒ **你說「A 的門檻很低」這件事，比你講的還更低。**

## 2. ★★ 真正的槓桿是寬度，而 3 倍寬度是樹上現成的

`llama-context.cpp:5386-5391`：draft ctx 一次算好 **3 個 token × 8 ids = 24 個**，
而現有程式碼只取 **j=0 一行 = 8 個**（理由是「verify 從第一個預測 token 開始驗證」）。

那個理由對「prefetch 的優先順序」成立，對「prebind 的覆蓋率」**不成立** ——
prebind 要的是 union 的全覆蓋，不是第一個 token 的精確。

```
預測 1 個 token ( 8 ids/層): q 上限 51.6% -> Dt/s  +5.4%   <- 現況
預測 2 個 token (16 ids/層): q 上限 76.3% -> Dt/s +12.3%
預測 3 個 token (24 ids/層): q 上限 91.1% -> Dt/s +19.5%   <- 樹上現成，只需改一行
預測 4 個 token (32 ids/層): q 上限 100 %  -> Dt/s +25.8%   <- + prev_token 的 8 個
```

**寬度的代價僅僅是查表，不是 fill**（寬度 24 的影子 ensure 估 38.3 ms，GPU 窗口 129.8 ms，
餘量 **3.39×**；而池有 143 可用槽/層、union 只有 15.5 ⇒ 開槽壓力根本不是約束）。

⇒ **「把 j=0 改成 j=0..n_tokens-1」是整個 A 方案裡最便宜、最該先做的一步。**

## 3. 相關性：你的直覺對，我把它量化了

用一個共用隨機效應 `r_i = logistic(mu + sigma*z)`（z 整層共用）當旋鈕：

| sigma | f_clean（q=0.60） | Δt/s |
|---|---|---|
| 0.0（獨立，你的 33% 世界觀） | 38.3% | +7.2% |
| 1.0 | 50.1% | +10.3% |
| 2.0 | 65.5% | +14.7% |
| 3.0 | 74.8% | +17.5% |

因為 `r^U` 對 r 是凸的，Jensen ⇒ 層內正相關**確實**把 `E[r^U]` 拉上去。
⇒ **你說「實際命中率可能比 33% 高」是對的**，而且方向可證。

**但它買不到一個數量級**：sigma 從 0 拉到 3（很強的相關）只換到 +10 個百分點，
而寬度從 8 拉到 24 換到 +14 個百分點且**不靠假設**。
⇒ **先買寬度，相關性當安全邊際，不要當主要論據。**

## 5. ⚠ 一個已經實測過的負證據：M5 prerouter 的 precision = 4.2%

樹上**已經有一個預測器被量過命中率**（`llama-expert-cache.cpp:1446-1521`，
`CGC_PREROUTER`），`docs/M3_M5_CLOSURE_2026-09-17.md` 記錄：

```
precision = 4.2%（B 臂）/ 12.8%（短序列）
queued / pred_total = 1062 / 64320 = 1.65%
```

**隨機猜的基準是 8/256 = 3.1%。4.2% 幾乎等於隨機。**

解讀（重要，不要誤用）：

- 它用的是**全域頻率直方圖**（每層取歷史路由次數最高的 8 個）。
  4.2% ≈ 隨機 ⇒ **路由的邊際分佈幾乎是平的，沒有「永遠熱」的專家**。
- 它**不能**否定 A：A 用的是時間局部性（prev token 87%、draft ids），
  與邊際分佈平不平**完全相容**（可以「每個專家長期一樣熱」但「相鄰 token 高度重複」）。
- 它**能**否定 C（見 §7）：C 的機制正是「按路由直方圖重分配」。

⇒ 你說「F2 的 null 不能用來否決 A」正確；同一句話對 M5 也成立，
**但 M5 的數字順手把 C 的前提打掉了。**

## 6. B（slot 間接化）：同意「先做 A，用 A 的命中率判斷 B」

補兩個 B 的前置條件，是你那段的隱含前提、但沒寫出來：

1. **miss 必須 = 0** —— 不只是「機率很低」。A 的 miss 是「掉回慢路徑，退化成今天」；
   B 的 miss 是「slot 裡沒有資料 ⇒ 靜默算錯」。同一個 miss rate，兩者嚴重性差一個等級。
   ⇒ 判準不能用 A 的 `fast/(fast+slow) >= 0.5`，要用「**在最長一輪裡 miss 數 = 0**」這種
   無容忍的條件，而那需要的是上界不是平均值。
2. **A 量到的東西不直接等於 B 需要的東西。** A 的量測單位是「層」（這一層乾不乾淨）；
   B 需要的是「**任何一層、任何一刻**」。⇒ 就算 A 的 q 到 0.95，B 仍可能不合格。

⇒ **A 的結果只夠決定「B 值不值得開規格」，不夠決定「B 可以上線」。**

## 7. C（提高有效容量）：同意是次選，但你的理由可以再硬一點

你說「頭痛醫頭，而且只是把問題搬到別層」。補兩條：

1. **C 的機制前提可能根本不成立。** C 靠「按路由直方圖按層重分配」，
   而 §5 的 M5 實測說直方圖幾乎是平的（4.2% ≈ 隨機 3.1%）。
   直方圖平 ⇒ 沒有哪層特別擠 ⇒ **重分配沒有可搬的東西**。
   ⇒ 不是「搬來搬去」，是「沒得搬」。
2. **但 C 對 A 有放大作用，這點你沒提到**：A 的 `r = p_res0 + (1-p_res0)*q`，
   `p_res0` 是它的地板也是它的放大器。

   | p_res0 | 寬度 8（q=0.52）的 Δt/s | −10% 需要的 q |
   |---|---|---|
   | 0.85 | +5.5% | 0.731 |
   | 0.90 | +7.4% | 0.662 |
   | 0.95 | **+9.6%** | **0.578** |

⇒ **C 不是 A 的替代品，是 A 的乘數。** 排序不變（先 A），但「C 完全不用看」是錯的：
`p_res0` 每 +0.05，A 同樣的寬度就多賺約 2 個百分點。

## 8. ⚠ 一個必須先拆掉的不一致（否則 A 的定價沒有地基）

`p_res0` 目前有兩個互相矛盾的來源：

| 來源 | 值 |
|---|---|
| `llama-context.cpp:5380` 註解「15% of selected experts are non-resident」 | p_res0 = 0.85 |
| 由 F1 模型 `cb = 0.46*L + 0.695*M` 反解實測 cb=39.3 ms | M ≈ 30 次 fill/step ⇒ p_res0 ≈ **0.95** |

第二個算法：40 層 × 15.5 union × (1−p_res0) = 30 ⇒ 1−p_res0 = 4.8%。
**兩者差 3 倍。** 而且反過來驗算：若 p_res0 = 0.85，則
`0.695 × 93 次 fill = 65 ms`，單 fill 項就超過實測的 cb 39.3 ms ⇒ **F1 的係數與
ntok=4 的實測不相容**（兩者必有一錯，或來自不同 regime）。

⇒ 這就是為什麼本工具**不用 F1 的係數**、改用校準過的線性代理。
**p_res0 是階段 0 必須量出來的第三個數字**（前兩個是 q(m) 和真實 uni_size）。

## 9. 併回：D（攤薄）的死因和你說的不一樣，而 A 會把它救回來

你說「k=3 比 k=2 慢，因為 ntok 變大 ⇒ fill 變多，與攤薄預期相反」。兩點修正：

1. **「k=3 比 k=2 慢」這個證據本身不乾淨**：k=3 ⇒ ntok=4 會跨過
   `ggml-metal-ops.cpp:2590` 的 Q_K 家族 `ne11>=4` 門檻（換 `mul_mv_ext`、不同 PSO）。
   乾淨的證據是**同 arm 內**的 ntok 比較（`gap_attribution.py`）：
   ntok 2→3 cb 幾乎不動，ntok 4 才是斷崖（×3.4-4.3）。
2. **真正的死因是分母不是分子。** 攤薄要攤在「**接受**的 token 數」上，
   而 `emit_tok_per_round = 2.000`。ntok 從 2 加到 4 只是把**候選**變多，
   接受的沒變多 ⇒ 固定成本攤不到更多人。這跟 fill 變貴是兩件事，而且這個更致命。

**但 A 會把 D 翻正**（這是 A 的第二個價值，你沒提到）：

| | ntok=2（現況） | ntok=4（現況） | ntok=4 + A（q=0.91） |
|---|---|---|---|
| union（真工作） | 65.7 | 120.1 | 120.1 |
| gap（純浪費） | 25.2 | 60.4 | ~22 |
| step total | 96.5 | 186.0 | ~147 |

union 從 65.7 → 120.1 只漲 1.83×（**次線性**，2× 的 token 沒換到 2× 的工作），
所以只要 A 把 gap 那 35 ms 拿掉，ntok=4 才第一次比 ntok=2 划算。
⇒ **D 不是獨立的方向，它是 A 的下游。** 單獨做 D 是負的；A 做完 D 自動變正。

## 10. 階段 0 儀器：gate 改寫（取代原設計 §7 的門檻）

原設計寫的「`all_cov_layers / n_routable < 0.5` ⇒ 停」要改，理由見 §1.2 與 §4：

```
CGC-PREBIND: layer=%u uni=%zu pred=%zu cov=%zu cov_pct=%.3f
             cold=%zu all_clean=%u
```

三個數字、兩個 gate（**事先寫死**）：

| 量 | gate | 不過就 |
|---|---|---|
| `p_res0`（真實常駐率，順手量） | 只記錄 | —— |
| **`cov_pct`（= q）** | **q(m=24) ≥ 0.73** | A 不值得，改走 `pread_usec` 路線 |
| `all_clean/n_routable`（= f_clean） | 只記錄，用來驗模型 | —— |

- 之所以 gate 換成 q：**q 是可以直接跟 §4 的門檻對齊的量**，而 `all_clean` 是 q 的函數，
  用函數當 gate 等於把兩件事混在一起。
- 同時要印 **真實 `uni_size`**（`CGC-HOOK` 現在截斷在 16，看不到真的 U）
  ⇒ U 是本模型裡指數的位置，錯 1 個就差很多。
