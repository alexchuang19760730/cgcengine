## 1. 為什麼「位址／位元組」不是前線（更正一句流傳過的說法）

「同 ids、同池佈局、gather 讀到**不同位元組**」這個敘述 **在 09-17 09:20 就被否證**
（`MEMORY_S1.md:94` 的標題就是它）。
§9.18.7（`own=`，11:2x，105 key／1200 列）的定論是：

| | 同臂控制 | A/B |
|---|---|---|
| verdict | `SAME=105 DIFF=0` | `SAME=0 DIFF=105` |
| causes | `SAME=1200` | **`ROUTING=477`／`SAME=723`**，**`CONTENT=0`、`SLOT-REUSED=0`** |

⇒ **載體是「拿到的專家不同」，位置在 gather 上游（routing／mapping）。**
**`op->src[2]->data` 那種位址讀數不是前線 —— 不要照那一句去做。**

## 2. 主嫌被劃掉：`CGC-SLOT-TABLE-CLAMP`

原本的推理（`llama-context.cpp:4559-4565` 的註解，本身寫得很清楚）：池路徑的 **leaf** 對非常駐專家寫
`−1`（響），而 **table 寫入把它 clamp 成 `0`**（`zero_slot` 綁在 MTP fast path，S1 是 MTP=0）
⇒ `mul_mat_id` 讀到**別的專家的權重**，而且**靜默**（0 是合法索引）。

**實測（只讀 log）**：

```
llama_server_20260917_130443 / 130721 / 131247 / 132734   （09-17 13:04–13:28，四支）
  S1 slot-table: publishes=1599 clamped_selected=0 clamped_table=295815 changed_entries=… consumed_changed=198…262
  CGC-SLOT-TABLE-CLAMP: site=pool verify il=1..4 clamped=185/256 (no consumed id affected: sel_wrong=0)
```

- **`clamped_selected=0`、`sel_wrong=0`：每一臂、每一層。** 被消費的 id **從來沒有**被 clamp。
- `clamped_table=185/256`（≈72%）是**整張表**的非常駐比例，**每一輪都一樣 ⇒ 沒有資訊**（CONVENTIONS B1）。
- **這個計數不是同義反覆**（先自我否證過）：兩個呼叫點
  `llama-context.cpp:6400`（`site=fast`）與 `:6551`（`site=pool`）都傳**本地 `ids`**，
  而那個 `ids` 正是同一段 `memcpy(t_ids->data, ids, …)` 寫進 ids tensor 的那一份
  ⇒ **它數的就是消費者會讀的那組 id**。

## 5. 下一件事（唯一）：`exp=` 的來源換成 host 現算

`cgc_expect_lookup`（`llama-context.cpp:3277-3296`）現在讀 `cache_remap_tensors[il]`，
而 `llama-graph.cpp:2190-2191` 的 `cgc_slot_table_gpu && il >= cgc_s1_min_il` 分支
**不建 host remap leaf** ⇒ 對 `il >= 1` 沒條目 ⇒ 實跑 `exp=none`。

**修法**：不要讀 leaf，**改成在 host 現算 `exp[j] = st[e_j]`**。

- `st` ＝ `llama_expert_cache::slot_table[layer * n_expert + expert]`（`llama-expert-cache.h:151-155`）。
- `e_j` ＝ 呼叫點手上就有（`ids` 與 `st` 在 `cgc_publish_slot_table_counted` 附近同時可見）。
- **不需要新 env、不需要內核**（§9.18.8 已寫死的設計）。
- 比較器的 map 軸已經在：`OK`／`LOST`（該臂裝置讀了自己 host 沒指定的 slot）／`NO-EXP`。

**⚠ 動手前的協調**：`src/llama.cpp/ggml/src/ggml-metal/ggml-metal-ops.cpp` 有**未提交**的
§9.18.9 改動（`CGC_IDS_STRIDE` 8→64 ＋ 印表機 clamp，+27/−2），作者**不是任何被追蹤的 session**

## 6. 同輪結清、與 S1 無關的一條：`cache` 桶的 120 個 CPY **不可摺疊**

`src/llama.cpp/src/models/delta-net-base.cpp:509-526` 在 `n_rs_seq != 0` 時每層建
`K = n_rs_seq + 1` 個 `ggml_cpy`。`n_rs_seq = draft.n_max`（`common/common.h:395-400`，我們是 3 ⇒ **K = 4**）。
`s_slot = K − t` ⇒ **K 個相差一步的狀態快照寫進 K 個不同 slot**，讀者是回滾環
（`llama-memory-recurrent.cpp:184/396`）。來源窗**遞增**、目的 slot **遞減** ⇒ 需要**負 stride**，
而 ggml 的 `nb` 不能為負 ⇒ **單一 cpy 表達不了 ⇒ 這條作廢。**

附帶（值得記）：`K = n_rs_seq + 1` ⇒ **MTP 一開就每層多 4 個 CPY** —— MTP 的成本不只在 verify 圖。
