0. Pool 大小 vs 確定性 — 完整曲線（甜蜜點實驗方法）

實驗設計（如何複現）

探針：qa-zh profile 的 15 + 27 = ? 只回答數字，正確答案「42」

請求參數：temperature=0, seed=0, max_tokens=16（greedy decoding，理論上應完全確定）

連發：同一 payload 連續發 10 次（或 6 次），統計輸出分布

判定標準：輸出全部為「42」= 確定；出現「22」= logits 邊界翻轉；出現「4×」或 echo = 污染

變更 pool 大小：CGC_SERVER_EXPERT_CACHE_BYTES=4294967296 / 6442450944 / 8589934592 / 10737418240（4/6/8/10GiB）

對照組：全 exact（CGC_VERIFY_DECODE=0 CGC_DRAFT_DECODE=0）＝ 零 ZERO-slot 的理論上限

監測：log 中 CGC-COLD-GUARD 觸發次數（guard 擋住走 exact 的次數）

每組配置重啟 server（改 pool 大小必須重啟），並記錄 RSS 與 decode t/s

核心結論（直覺被數據否決）：

  1. 更小 = 更糟，不是更確定——4/6GB 下 guard 確實更常觸發（32/11 次），但沒觸發的層照走 ZERO，部分污染依然存在；更糟的是小 pool 的 LRU churn 讓「已 resident」的 expert 也被換掉 → fast path 命中率暴跌、exact path 也要重新 fill → 品質崩到 50-60%
  2. 確定性真正的來源是「冷 expert 少」（8GB 以上），不是「guard 擋得多」
  3. 8GB = 16GB 機器的確定性甜蜜點（90%，28 t/s）——不值得為省 2GB 換 50-60%
  4. 殘餘 1/10 抖動來自冷啟動期（見 §1 根因）

今日結論（取代 §0 舊「4/6GB 品質崩 50-60%」）：

  1. 8GB 仍是甜蜜點：6GB -13%、4GB -39% decode；品質全 1.0（現代 Cold Guard 下 cold expert 走 exact 而非 ZERO，小 pool 不崩品質、只掉速度——與舊 guard 時代的「4GB 品質崩 60%」不同）
  2. 速度 ∝ cold 比率近乎線性：每降 1% cold(ZERO) ≈ +0.9 t/s（7.2%→16.1、9.6%→14.0、18.7%→9.85）。真正的速度槓桿是「降 cold 比率」（讓 pool 裝 decode 真正要的 experts），不是 pool 大小本身

根因（log 證據）：

  1. 09-04 的 0.97 是 ZERO 污染時代的假象：flashkv0516 log 顯示 cold(ZERO)=88790 (53.4%) — 每步 53% 的 expert 是 ZERO-slot 污染的 weights。draft 與「污染後的 target」用同一批錯誤 weights → 高度一致（0.97）但兩邊都錯
  2. 09-07/09-08 guard 硬化後 target 變正確：phase discrimination（prefill exact）+ Cold Guard + DRY + loop guard 讓 ZERO 污染大減 → target logits 正確 → draft 與正確 target 的差異被暴露 → accept「誠實地」掉到 0.45
  3. decode 25-37 t/s（09-04）也是污染速度：ZERO-slot 免載入 → 快但品質沒人驗證；現在 15-17 t/s 是品質 1.0 換來的誠實速度

結論：accept 0.45 不是 regression，是系統變正確的副作用。要提升 decode 不能靠放寬採樣（DRY/temp/pp 全部無感），只能讓 draft 本身變準（draft ctx 更高精度載入、或更準的預測來源）。

1. IQ3_XXS 抖動根因：不是 expert cache，是 logits 邊界 + GPU 浮點

決定性實驗：全 exact（CGC_VERIFY_DECODE=0 CGC_DRAFT_DECODE=0，零 ZERO-slot）15 連發仍抖——42×13 / 22×2（13% 抖動率），與 fast path 的 10% 幾乎相同。這推翻了「ZERO 污染是抖動源」的方向。

機制：「42」與「22」的開頭 token logits 差距極小（±1e-4 級），Metal parallel reduction 順序受並發負載影響 → 邊界 token 偶爾翻轉。expert cache 只是放大器之一，不是必要條件。三個條件疊加：① 模型 logits 邊界接近（必要條件）② GPU 浮點非確定性（扳機）③ expert cache 只是放大器之一。

發現證據
