# G4：那「45% 沒有名字」不是長尾，是**被儀器的 top-5／≥5% 上限蓋住的第 6 名以下**

2026-09-20 13:3x–13:4x，線A (ace)。載體：`m123_oracle_gate.py --tag g4-tail --env CGC_GPU_NODES=1 --env CGC_GPU_OPS=2`
（`Backup/cgc_logs/llama_server_20260920_133610.log`，125 段）。儀器改動：`ggml-backend.cpp`（+16/−3，見 §4）。

---

## 0. 兩句話

1. **不是一條長尾。**每個 segment 的**前 5 名完全一樣**（`node`／`cache`／`ffn_moe_`／`ffn_moe_add`／`norm`），
   已命名佔比**中位只有 54.6%** ⇒ 殘量是**第 6 名以下、每個都 <5%** 的一群。
2. **放寬上限就全部命名了**：中位已命名 **54.6% → 86.9%**，而**沒有任何單一 kind 超過 12.8%**
   ⇒ 這與 G4 自己的 `no_single_lever` 一致：**成本是攤平的，槓桿是「融合」，不是「找熱點」。**

---

### 2.2 ★ 兩個結構性事實

1. **沒有任何單一 kind 超過 12.8%**；前三名（`ffn_moe_`／`node`／`ffn_moe_add`）合計 **36.1%**，
   而它們**都是 MoE FFN 的支撐 op**（未融合的 elementwise ＋ 殘差加 ＋ 家族前綴）。
   ⇒ **G4 的槓桿是「融合一群同尺寸的 op」，不是「優化一個熱 kernel」。**
2. **尾部由 gated-delta-net 的支撐 op 主導**：`conv`／`k_conv`／`z-`／`gdn_out`／`attn_norm`／
   `dnqkv_proj`／`dnbeta_proj`／`beta`／`q_conv`／`dn_normg_mul`／`linear_attn` 合計約 **15–16% of tot**。
   其中 `k_conv`／`z-`／`gdn_out` **三個都剛好 51.98 ms** ⇒ **同工作權重**，正是「一族同尺寸 op」的簽名。

### 2.3 ⚠ 兩個讀法上的保留（不要過讀）

- 多個尾部 kind 印成 **0.10 ms（2 位小數）**。這**可能**是列印精度（真值介於 0.095–0.1049），
  **也可能**是那些 op 的值真的相同。**同一份 log 支持後者**：`k_conv`／`z-`／`gdn_out`
  在 125 段合計上**逐位元同值 51.98 ms**，而它們在每一段的百分比也相同（2.6%）——
  這只能是**工作權重與節點數相同**，不是量測底噪。⇒ **「這 15 個在解析度下限」這個讀法收回**；
  正確的說法是「**它們同值，因為同工作權重**」。
- **殘量 13.1% 仍未命名**：它是低於 1% 門檻的部分。要再往下走只能**再放寬**（例如 `=3` 給 0.1% 門檻），
  但那會開始把**圖的固定開銷**與**真正的 op** 混在一起 ⇒ 建議先把 §2.2 的融合路線做完再回來。

## 3. 對 G4 的結論

| | |
|---|---|
| **可及空間（不變）** | `union` 104.87 ms vs 權重地板 **19.5 ms/步** ⇒ **5.4×**；等效頻寬 22.3 GB/s ＝ M4 的 19% |
| **機制（本節新增）** | **攤平在 ~25 個已命名的 kind 上，沒有任何一個 >12.8%**，而它們分成兩族：**MoE FFN 支撐 op（前 3 名 36.1%）** 與 **GDN 支撐 op（~15%）** |
| **所以下一步** | **融合**（`node` 的未融合 elementwise、`ffn_moe_add` 的殘差加、GDN 的一族同尺寸小 op），逐族做，沒有單一槓桿 |
| **不是** | 找不到熱點 kernel —— 熱點**不存在**，這正是 `G4.no_single_lever` 的實測版本 |

## 4. 儀器改動（+16 / −3）

`CGC-GPULAYK` 原本是 **top-5、每個 ≥5%**。改成：

```cpp
int kop_topk = 5, kop_floor_div = 20;   // 20 => 5% floor
if (const char * ops_lv = getenv("CGC_GPU_OPS")) {
    if (atoi(ops_lv) >= 2) { kop_topk = 16; kop_floor_div = 100; }
}
```

- **`CGC_GPU_OPS=1` 的路徑逐字不變** ⇒ 既有記錄（含 `docs/GPU_NODE_ATTRIBUTION_*` §56–§62 的數字）可複現。
- **刻意複用既有門控、按值分級，而不是新增 env 名**：`CGC_GPU_OPS` 已在 `run_server.sh` 的 allowlist 裡，
  而那個區塊**正被另一條線編輯**；blob-staged 的加法會被他們下一次提交同一區塊時還原。
- 行緩衝 `600 → 1600`（16 個 kind 塞不進 600 bytes，而 `snprintf` 截斷會**靜默丟掉**這次要讀的尾巴）。
