2.1 Expert Cache Hook 細項分解（已實測）

CGC_HOOK_PROFILE instrumentation：steady state 平均 100 µs/次，每 token 40 層 = 4.0 ms/token，佔總延遲 10%。

技術細節

// kernel_moe_remap_generate（Metal）
// 輸入：ids tensor [n_expert_used, n_tokens]（top-k 輸出）
//       slot_table_gpu [n_layer * n_expert]（只讀副本，40KB）
//       layer_index（當前層）
// 輸出：remap tensor [n_expert_used, n_tokens]（expert id → slot idx）
kernel void kernel_moe_remap_generate(
    device const int32_t * ids,
    device int32_t * remap,
    constant const int32_t * slot_table_gpu,
    constant int32_t & layer_index,
    constant int32_t & n_expert,
    uint32_t tid [[thread_position_in_grid]]) {
    int32_t expert_id = ids[tid];
    int32_t slot = slot_table_gpu[layer_index * n_expert + expert_id];
    remap[tid] = (slot >= 0) ? slot : 0;  // cold → ZERO-slot
}

slot_table 同步策略：steady state 下 slot_table 更新不頻繁（大部分是 hit），可在 ensure_batch 後異步全量拷貝到 GPU（40KB，開銷極小）。DBUF hook-time refill 的 bg fill 完成後也需要同步。

16GB Mac M4 Max 理論天花板內存帶寬公式推導 · 70-94 tok/s 原始上限

物理極限說明：M4 Max 16GB 統一內存帶寬 ~100-120 GB/s。Qwen3.6-35B-A3B IQ3_XXS 模型 ~13GB，每 token 激活 ~3B 參數（8/256 experts），對應 ~3-4GB 內存讀取。理論上限 = 帶寬 / 每 token 字節數 ≈ 100GB/s / 3.5GB ≈ 28.5 t/s。考慮 KV cache、系統開銷，實際天花板 ~28-30 t/s。當前 25.17 t/s 已達理論上限的 84-90%，剩餘優化空間有限但仍可挖掘。

7.3 32GB 升級路徑

如果 16GB 達到瓶頸
32GB Mac 可使用更大的 expert pool（12-16GB），捕獲 95-99% 的 routing mass（vs 16GB 8GB pool 的 ~76%），從根本上解決 cold expert 問題。預期速度 30-35 t/s，且品質更穩定。同時可啟用 async bg prefetch（更大的 pool 減少 race 風險）。
