v6 Fix 邏輯

在 server-common.cpp 中,當 prefill 結尾是結構化 marker(換行、反引號、列表符號等),跳過 THINK_SEED 注入,避免 model 進入 think loop。

// pseudo-code
if (cgc_prefill_ends_with_structural_marker(prefill_text)) {
    skip_think_seed = true;  // 不注入 THINK_SEED
}

v7 Fix 邏輯

在 server-common.cpp:799 實作 cgc_patch_coding_stop,偵測 code fence open(28 種 fence_languages: python/py/c/cpp/c++/java/...)的結尾 marker,把 stop 列表從 ``` 替換為 ```\n\n,提供 cgc_code_strict_stop=1 escape hatch。

// tools/server/server-common.cpp:799
void cgc_patch_coding_stop(std::vector<std::string> & stop_sequences) {
    if (last_user_block_ends_with_code_fence_open()) {
        for (auto & s : stop_sequences) {
            if (s == "```") s = "```\n\n";  // 加 newline 避免 fence 內部 trigger
        }
    }
}

應用於兩個 endpoint: /completion (line 874) 跟 /v1/chat/completions (line 1201)。

3.2 性能 trade-off 解讀

看似 v7 比 prod-25ts 慢? 不是的。prod-25ts 的 25.29 t/s 是長答場景的數字,當時 qa-zh 短答仍有 0000 loop 問題,只能量到長答。v7 之後三場景都量到合理值,平均 22.47 t/s 是更全面的數字。對比單一場景,實際上 v7 在 coding 場景比 prod-25ts 略快(27.30 vs 26.0)。

6. 部署注意事項與升級指南

6.1 從 prod-25ts 升級到 v7+Softpool (current)

重大變更: 從 prod-25ts 升級到 4a0d4d258 涉及 chat template 行為變更,客戶端整合需要重新驗證。

升級步驟:

  1. 備份當前 .replay_bench_baseline.json: 
    cp .replay_bench_baseline.json .replay_bench_baseline.json.bak.$(date +%Y%m%d)
  2. Pull 最新 commit: 
    git fetch origin
git checkout 4a0d4d258
  3. Rebuild dylib: 
    cd src/llama.cpp && cmake --build build -j8 --config Release
cd ../..
  4. 重啟 server: 
    bash scripts/run_n30cache.sh  # 或生產環境對應腳本
  5. 驗證 baseline: 
    bash scripts/check/replay_bench_compare.sh
    預期結果: improvements=2 regressions=0 neutral=10(若 peak_rss_mb 從 5940 降到 5771)
  6. 客戶端整合測試:
    • qa-zh 短答: 應無 0000 loop
    • longform-zh 長答: 應無 think loop
    • coding 場景: 應無 1-token stop

6.2 環境變數生產配置建議

生產環境的「最佳實踐組合」:

# Expert Cache (預設全 OFF,建議打開部分)
LLAMA_EXPERT_CACHE_ALLOW_NGL=1   # Metal fast path
CGC_SOFT_POOL=1                  # Softpool 三層
CGC_SOFT_POOL_L0=8               # L0 容量(剛性)
CGC_SOFT_POOL_L1=32              # L1 容量(LRU)

# Chat template
--chat-template-file models/templates/Nail-Qwen3.6-Minimal-Chat.jinja

# 守護機制 (生產關閉,CI/A/B 打開)
# CGC_EXACT_CACHE_VERIFY=1       # V1(打開 -30% t/s)
# CGC_LOGITS_ORACLE_DUMP=...     # V2(打開 -2% t/s)

6.3 16GB Mac 設備特別注意

OOM 風險: 16GB Mac 設備 L4 path + Softpool 全開可能 OOM。建議:
  1. 設 LLAMA_EXPERT_CACHE_L4_SKIP_LAYER0=1(省 ~250MB)
  2. 縮 CGC_SOFT_POOL_L1=16(省 ~500MB)
  3. 避免同時打開 V1 hash(會再多用 ~200MB 暫存)
