目標：修復 devserver 的品質退化問題（think loop、重複輸出、echo prompt）， 先確保語意正確，再於下一個里程碑恢復 25+ t/s 速度。

一、問題背景

devserver 使用 Qwen3.6-35B-A3B-MTP IQ3_XXS（denseIQ4X）＋ MTP 投機解碼 ＋ expert cache 4GB ＋ ngl=99。先前對拍發現：

Profile品質分數（修復前）症狀
qa-zh0.500echo prompt / think loop
longform-zh0.3330000 或重複輸出
coding0.667重複「```python」

二、根因分析（三層）

  1. expert cache pool 路徑：ngl=99 全 offload 時，pool 的 ZERO-slot 路徑 （cold expert 未填入 → 零權重）會造成品質退化。Cold Guard 強制 ensure_batch 填滿 cold expert 可恢復品質，但速度會掉（這是速度問題的根源，下一里程碑處理）。
  2. think loop：Qwen3.6 原生模板在 assistant 前不加任何東西，模型自行決定是否 進入 thinking 思考模式。IQ3_XXS 量化下首 token 分布被噪聲主導， 模型頻繁誤入 think loop（ thinking\n\n response\n\n 無限循環）。
  3. 重複輸出：IQ3_XXS（3.0625 bpw）低比特量化下，默認採樣參數過「鬆」， 放大首 token 噪聲 → 模型進入重複循環（echo prompt 或重複短句）。

三、修復內容

1. no-think ChatML 模板（新增）

新增 src/llama.cpp/models/templates/Qwen3-nothink-ChatML.jinja， 在 assistant header 後注入 response 前綴，直接告訴模型 「思考已結束，開始回答」：

{%- if add_generation_prompt %}
<im_start>assistant
 response{%- if prefill_text %}
{{ prefill_text }}
{%- endif -%}
{%- endif %}

效果：完全消除 think loop。qa-zh 品質從 0.5 → 1.0。

2. IQ3_XXS 採樣參數（run_server.sh）

參數修復前修復後作用
--temp0.7（默認）0.4降低採樣隨機性
--top-k400（禁用）固定閾值保留噪聲 token
--top-p0.80.8保持 Qwen 官方 no-think 推薦

3. reasoning-format deepseek

--reasoning-format deepseek：即使模型偶爾生成 think 內容， server 會將其移入 reasoning_content 欄位，主內容保持乾淨。

4. Cold Guard 恢復 ON（已含於上一 commit 96522f4f9）

Cold Guard 閾值 0.30：當某層 top-k expert 的 cold 比例 > 30% 時強制走 ensure_batch 填滿，避免 ZERO-slot 零權重污染。這是品質正確的核心。
