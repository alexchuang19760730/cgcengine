## 1. 問題：一個 profile 共用一份關鍵字，讓「回顯題目」變成 PASS

舊評分器的 `required_any` 是**整個 profile 共用一個扁平清單**，逐題只換 prompt。所以答案鍵裡的字同時出現在**題目**裡時，把題目回顯一次就得分：

| profile | 題目 | 共用鍵裡被命中的字 | 後果 |
|---|---|---|---|
| qa-zh | 太陽系有幾個行星？請列出名稱。 | `行星` | 回顯即 PASS |
| qa-zh | 法國的首都是哪裡？ | `法國` | 回顯即 PASS |
| qa-zh | 請問 15 + 27 等於多少？ | `等於` | 回顯即 PASS |
| math | 請計算 25 × 4 等於多少？ | `等於` | 回顯即 PASS |
| reasoning | …貓需要睡覺嗎？請回答**是**或否。 | `是` | 任何含「是」的中文都 PASS |
| longform-zh | 請介紹巴黎的歷史、文化和著名景點。 | `巴黎`/`文化`/`歷史` | 回顯 + 湊足長度即 PASS |
| coding | 用 Python 寫一個函數**反轉**字串。 | `反轉` | 回顯即 PASS |
| coding | …計算兩個整數的**最大公因數**。 | `最大公因數` | 回顯即 PASS |
| translation | 請將「**人工智慧**正在改變世界」翻譯成英文。 | `人工智慧` | 回顯即 PASS |

## 2. 修正：兩把尺，並排輸出

`replay_bench_reference_v2.json` **刻意不動**，因為它就是舊尺的定義 —— 舊分數必須可重現。新尺寫在另一個檔案。

### legacy（舊尺）
與 37/48 基線逐位元相同。保留作為歷史比對。
**已驗證**：對 153 個案例（48 筆真實記錄輸出 + 105 個合成邊界）與 `HEAD:scripts/check/bare_48.py` 的 `score_one` 逐項比對，**0 個不一致**。

### strict（新尺）
1. **每題自己的答案鍵**（`bare48_answer_keys_v1.json`）。鍵的選法有一條硬規則：**題目本身不能滿足它**。
2. **結構性回顯閘門**（與關鍵字無關）：
   - `lcp`：答案開頭與題目逐字相同 ≥ 10 個正規化字元
   - `span`：題目裡一段 ≥ 18 個正規化字元的連續文字原封不動出現在答案裡
   抓的是「複述題目當作答」這個實際觀測到的行為，而不是靠關鍵字猜。
3. **開放式題目（longform / writing）改用 novelty 規則**：答案必須含 ≥ N 個「題目裡沒出現過」的字元。回顯的 novelty = 0，所以這個規則**也是回顯證明**。
   （設計理由：開放式作文無法用關鍵字評分而不發明需求。舊的扁平清單在這裡既擋不住回顯、又會放行湊字數的無關內容。）
4. **誠實遵守 `ok_finish_reasons`** —— reference 自己宣告了這個欄位，舊評分器從未讀取它。

### strict-core
strict 但**不做**每題 length 覆寫。用來把兩個獨立的改動分開歸因：
- 「修扁平 `required_any`」
- 「修 harness 的長度假陰性」：`qa-zh #1` 的 `length_max=200` 擋掉正確的 332 字行星列表（題目明說「請列出名稱」）；`qa-zh #0/#3` 的 `length_min=4` 擋掉「巴黎。」(3 字) 與「台北」(2 字)（題目明說「請簡短回答」）。

## 3. 機械證明：回顯不再得分

```
$ python3 scripts/check/bare_48.py --selftest-echo
餵入樣本: 192          # 48 題 × 4 種回顯變體（原樣 / 2x / 3x / +答：）
舊尺放行: 59  (30.7%)  <- 這些全是回顯假陽性
新尺放行: 0
PASS：新尺在 48 題 × 4 種回顯變體上全部 FAIL
```

這個自測**不需要 server、不需要模型**，所以它是一個可以隨時重跑的迴歸鎖 —— 任何人之後改答案鍵，只要不小心讓某題可被回顯命中，它就會紅。

## 4. 實測落差（重播 9/48 run 的記錄輸出）

因為過去的 run **只存了 120 字的 `output_preview`**（沒有全文），所以在舊結果上重評只能用前 120 字。這足以判定回顯（回顯發生在輸出開頭）但不足以判定後段的關鍵字或長度。

```
run                                old        new        echo-rm   kwd-rm(LB)
cap8 (the 9/48 run)                9/48       3/48       3         3
```

逐 profile：

| profile | old | new |
|---|---|---|
| qa-zh | 3/8 | 2/8 |
| longform-zh | 1/6 | 1/6 |
| coding | 0/11 | 0/11 |
| math | 1/8 | 0/8 |
| reasoning | 2/5 | 0/5 |
| writing | 0/5 | 0/5 |
| translation | 2/5 | 0/5 |
| **TOTAL** | **9/48** | **3/48** |

**那 3 個留下來的**是真正答對的：`15 + 27 = 42`、`一年有12個月份`、巴黎的歷史文化景點介紹。

**必須標註的兩個誠實界線**：
- `reasoning #2`（雞兔同籠）在重播裡被判 FAIL，但它是**預覽截斷的假陰性** —— 輸出前 120 字已經在正確列式（`總頭數 = 30 隻`、`建立方程`），20/10 的答案在 120 字之後。真跑很可能 PASS。所以 3/48 是**下界**。
- `kwd-rm` 那一欄是**下界**，因為關鍵字可能落在第 120 字之後。

## 5. 為什麼這次的結果可以回頭重評（下次不行）

`--dump-full` 是這次新增的。沒有全文，評分器改版後就**無法**在舊結果上重跑比較 —— 這正是本次只能用預覽重播的原因。**建議之後所有品質 run 都帶 `--dump-full`。**

## 6. 這對 37/48 的意義

37/48 是用**舊尺**量的，所以它包含同一個假陽性來源。**37/48 與 9/48 現在都不可直接比較**：要嘛用新尺各重跑一次，要嘛把兩者都標成「舊尺數字」。

判讀規則建議：
- 一律以**新尺**當判定「有沒有回答」的那把。
- 舊尺數字只在「與歷史同一把尺」的意義下引用，且必須標明。
- 新尺分數一定比舊尺低 —— 這是**預期**結果，不是退化。

## 7. 已知限制

- 開放式題（longform 6 題 + writing 5 題）沒有關鍵字鍵，只靠 echo + length + novelty + loop + forbidden。**長度足夠、非回顯、但離題**的答案仍可能通過。舊尺其實也擋不住（13 個共用關鍵字），而且它會放行回顯。
- 回顯閘門的門檻（lcp 10 / span 18）是選出來的，不是調出來的：48 題 × 4 變體的 192 個陰性樣本全部 FAIL，153 個 legacy 一致性案例全部一致。真實答案的誤殺風險未在大規模資料上量測。
