## 2. M-25：判據失效 → 但結論更硬

### 2.1 09-21 的判死理由是**列舉式**的

> L1 1.33% ＋ L2 0（K5=C）＋ L3 0 ⇒ 沒有任何一格在供貨

這種判據有一個結構性弱點：**它活在「列舉完備」這個前提上**。
只要出現一枚沒登記過的槓桿，整句話就失效——不需要任何一格被推翻。

### 2.2 今晚就出現了這樣一枚槓桿

附帶一個有用的交叉檢查：`CGC-EBTIMER` 同步量到 fill = **37.80 ms/step**，
而端到端差額只有 **30.8 ms/token** ⇒ **約 18% 的 fill 時間已經被 overlap 掉了**，
剩 82% 才是硬開銷。**可收回的是 30.8，不是 37.8。**

這是一枚**從未進過表**的槓桿，而且是表裡最大的一枚（佔 step 的 41%）。

⇒ **09-21 那句「沒有任何一格在供貨」，字面上已經不成立。**

### 2.3 但結論反而更硬：換成封頂判據

## 4. M-PF 與 layer-ahead prefetch 是**兩件不同的事**（別混為一談）

- **M-PF（背景 neighbour prefetch R=1）已撤回**：`L3_PREFETCH_RETRACTED` 的判據是
  步級 IO 309–429 ms ≫ 陰影 159.77 ms。
- **`CGC_LAYER_AHEAD_PREFETCH=1` 是另一套**（2026-09-19 落地，非預設 A/B flag）：
  用**上一個 token** 的 routing（相鄰 token 復用 ~87%）**提前一層**把 prefetch 排進去。
  它**從未進過里程碑表**。

它的天花板寫在 `llama-context.cpp:7244-7246` 的註釋裡：

> drain_layer(next) **DROPS** prefetches for the next layer that have not started yet, so
> only fills that actually land inside the window pay off. … it is why this is an A/B flag
> rather than a default.

⇒ 不建議給 M-PF 翻案。**但如果要追求 §2.4 的 15.1，它是比 3b 便宜得多的一張牌**
（改 1 個 env vs 動 C++ ＋ 重建 ＋ 搶窗口），值得先驗。
