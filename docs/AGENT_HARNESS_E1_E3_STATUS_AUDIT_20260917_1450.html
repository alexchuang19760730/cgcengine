2. 更正：E1「只結清一半」那句話是錯的（而且錯在量具）

PLAN §9 與 agent_harness/README.md 從 9/16 17:2x 起寫著：

> ⚠️ smoke 未跑：tb_loop/.venv 不存在、terminal-bench 未安裝、Docker daemon 未執行
> ⇒ 驗收只結清一半，import tb_loop.agents.prime_agent_adapter 目前止於
>   No module named 'terminal_bench'

那個結論是用 系統 python3 量出來的。事實是：tb_loop/.venv 存在（9/16 19:32 建立）， terminal-bench 裝在裡面，而 config.env 的 TB_VENV_PY 指的就是它。 用對直譯器：

$ PYTHONPATH=agent_harness agent_harness/tb_loop/.venv/bin/python \
    -c "import tb_loop.agents.prime_agent_adapter"
import OK -> .../agent_harness/tb_loop/agents/prime_agent_adapter.py
$ python3 -c "import tb_loop.agents.prime_agent_adapter"     # 系統 python3
ModuleNotFoundError: No module named 'terminal_bench'

同一份原始碼、兩個相反的結論，差別只在直譯器。驗收句寫的是「套件解析成功」， 沒有指定直譯器 —— 那個模糊處就是錯誤結論的入口（lesson eng-gate-0052）。

3. E1 真的有一支回歸沒修（程式，不是量測）

$ (cd agent_harness/tb_loop && .venv/bin/python scripts/local_rehearsal.py --help)
Traceback (most recent call last):
  File ".../tb_loop/scripts/local_rehearsal.py", line 48, in <module>
    from agent_harness.agents.codebuff_api_agent import CodebuffApiAgent
ModuleNotFoundError: No module named 'agent_harness'
連 --help 都跑不到 —— 失敗點在檔頭，不在功能裡。

成因是半轉換。同一個檔案裡：

# 保证能 import 到 tb_loop.agents.codebuff_api_agent     ← E1 時改好了
TB_LOOP_DIR = Path(__file__).resolve().parents[1]
for p in (TB_LOOP_DIR, TB_LOOP_DIR.parent):              ← 放進來的是 tb_loop/ 與 agent_harness/
    sys.path.insert(0, str(p))
from agent_harness.agents.codebuff_api_agent import ...   ← 但這行還是搬遷前的名字

agent_harness 本身不在 sys.path 上（它沒有 __init__.py， 是 namespace package，只有 repo 根在路徑上時才解析得到）—— 而上面那兩行按的是新佈局。 註解說的是對的，所以 review 會通過。

4. E2／E3 剩下的確實是量測 —— 但要分清哪一種

需要什麼端點可不可以換成遠端
T1 蒸餾（refine_engine.sh）一個會回答的模型 ＋ REFINE_ENGINE_MODEL 可以：它讀的是 harness 的紀錄（episodes／lessons），產出 decisions。LLM_BASE_URL／REFINE_ENGINE_MODEL 都是可設的
D6 欠帳（closed_loop.py A vs B）本機模型端點 ＋ 乾淨窗 不行：這一組實驗是圍繞本機模型的 ChatML／<think> scaffold 設計的，換模型等於換一個實驗
E3 本體（C vs D）同上不行：同上

端點現況（唯讀實測）：llm_client.py 預設 http://127.0.0.1:8080、 litellm_config.yaml 指 http://127.0.0.1:8083、4000 沒有 listener ⇒ 本機目前沒有現成的端點。所以「等窗」對 D6／E3 成立，對 T1 只是「等一個端點」。

5. 誠實邊界（不主張什麼）

  • smoke 沒有跑。本檔只主張「它的前置條件裡，.venv 與 terminal-bench 已具備、 缺 Docker daemon」——沒有主張 smoke 會過。tb run 這條路徑至今沒有在本機被執行過 （results/ 底下的是 9/3 的 Windows Git Bash 彩排與 wsl2_test）， 而未執行過的路徑不算「驗證過」。
  • 沒有起 colima。使用者先前要求停掉它，所以 Docker 這一格留給使用者決定。
  • 沒有動 E2／E3 的任何檔案。本輪只做稽核與兩處 E1 回歸的修復。
  • 文件更正的方法是 dated 註記，不是改寫。PLAN §9 與 README 的原文保留， 新增的是標了日期的更正列／段（本 repo 對「條文被推翻」的既有規定）。
