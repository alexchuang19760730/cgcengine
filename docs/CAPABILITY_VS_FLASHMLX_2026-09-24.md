# 我們的能力高於 FlashMLX 嗎 —— 分維度判決

日期：2026-09-24（承接 09-23 §EN-474 評估 + §EN-476 實測）
方法：**0 benchmark**，純靜態對比既有實測數字。標的＝ anemll-flash-mlx（Flash-MoE）。

---

## 0. 先拆「能力」——不拆就沒有答案

「誰比較強」在這裡是偽問題，因為兩邊跑在**相差 4~5 倍的機器**上：

| | 我方 | FlashMLX |
|---|---|---|
| 機器 | **M4 / 8 核 GPU / 16 GB 統一內存 / 無風扇** | **M5 Max / 128 GB** |
| 模型 | Qwen3.6-35B-A3B, UD-IQ3_XXS | Qwen3.5-35B-A3B, 4-bit |
| 交付 t/s | **12.57** | 47.1（slot-bank 128）/ 94.5（resident） |

絕對 t/s 差 3.7~7.5×，但**那不是演算法**。要回答「能力」，必須挑**無量綱**或**已歸一化**的指標。

---

## 1. miss 代價斜率 —— 唯一乾淨的可比指標 ★

定義：每 1pp 的 miss 吃掉多少 % 吞吐。**越低 = SSD path 越有效率。**

```
FlashMLX : 94.5 (100% hit) → 47.1 (82.7%)   損失 50.2% / 17.3pp = 2.90 %/pp
我們     : 15.14(100% hit) → 12.57(61.4%)   損失 17.0% / 38.6pp = 0.44 %/pp
```

⇒ **我們對 miss 的魯棒性是對方的 6.6 倍。**

判讀：對方 miss 17.3% 就**掉一半吞吐**；我們 miss 38.6% 只掉 17%。
原因（§EN-474）：我們的 miss 走 bg thread + 41 段填充，IO 部分被藏進 GPU 空檔（`cb` 只佔 step 17%）；
對方的 slot-bank miss path 表現得像**同步阻塞**。

⚠ 我們的 15.14 是外推（cb 全藏），非實測。用 `DEVICE_BUSY` 交叉驗證的 15.8 重算 ⇒ 0.48 %/pp，
結論不變。對方 94.5 是實測 ⇒ **這個對比對我們偏保守**。

---

## 2. 命中率錯配 —— 誰把「理論能吃到的」吃掉了更多

兩邊同為 35B-A3B / 256 experts ⇒ 借用我們實測的重尾上界（K=128 → 98.2%，K=143 → 98.9%）
**作為對方的上界是假設**，但架構同源，量級可信。

| | 覆蓋率 | 實測 hit | 上界 | **錯配** |
|---|---:|---:|---:|---:|
| **我們 PIN_PROFILE** | 55.9%（143 槽） | **89.4%** | 98.9% | **9.5 pp** |
| FlashMLX slot-bank 128 | 50.0% | 82.7% | ~98.2% | 16.2 pp |
| FlashMLX slot-bank 64 | 25.0% | 80.8% | — | 18.1 pp |
| FlashMLX slot-bank 16 | 6.3% | 59.5% | — | 39.4 pp |

⇒ 命中率我們高 **6.7pp**；按覆蓋率歸一化後錯配仍高 **6.7pp**。
⇒ **「重尾 + 靜態釘住」這個洞察，對方沒有用上**（他們用動態 slot-bank）。

### 反向：這個洞察在誰身上更值錢？

| | hit 提升 | 斜率 | 吞吐增益 |
|---|---:|---:|---:|
| 給對方用（82.7 → 89.4，+6.7pp） | 6.7pp | 2.90 %/pp | **+19%**（47.1 → 56.3） |
| 我們自用（61.4 → 89.4，+28.0pp） | 28.0pp | 0.44 %/pp | **+12%**（12.57 → 14.12） |

⇒ 反直覺但自洽：**對 miss 越敏感的系統，提命中率越值錢。**
我們之所以「只」值 12%，是因為我們本來就不太怕 miss。

## 3. 每專家位元組 —— 決定池能裝多少

| | per-expert | vs 我們 |
|---|---:|---:|
| 我們 IQ2_S×2 + IQ3_S | **1.0703 MiB** | — |
| FlashMLX 4-bit | 1.6117 MiB | **+51%** |
| FlashMLX UD-Q2_K_XL | 0.8965 MiB | −16% |

⇒ 我們比對方的**主力格式**省 34%（同 resident 多裝 51% 的專家）。
⇒ 但對方 UD-Q2 比我們再省 16% —— 那只是「選更低 bpw」，**在 llama.cpp 直接做即可**，
不構成換框架的理由（§EN-474）。

---

## 4. 純算力歸一化 —— 引擎本身有沒有量級劣勢？

排除 IO（100% resident）後：

```
我們 15.14  vs  對方 94.5   = 6.2×
硬件差距：GPU 核 8 → ~32-40（4~5×）＋ 頻寬 ~120 → ~400-500 GB/s（3~4×）
```

⇒ **6.2× 與硬件差距同階 ⇒ 引擎本身沒有量級劣勢，也沒有量級優勢。**
⇒ 也就是說：12.57 vs 47.1 的絕大部分，是「8 核 GPU vs 32+ 核 GPU」＋「16 GB vs 128 GB」。

---

## 5. ⚠ 一個反轉：對方的瓶頸跟我們不是同一個

```
FlashMLX UD-Q2 (0.94 MB, 少讀 44% 位元組) → 42.2 t/s
FlashMLX 4-bit (1.69 MB)                  → 47.1 t/s
```

**少讀 44% 位元組反而更慢。** ⇒ 對方的瓶頸不在 IO 位元組數（可能在 dequant / kernel / Python 開銷）。

而我們這邊 `cb` 與位元組數成正比，且已被設備層證實（`CB_IS_THE_DEVICE_RESULT`：per-miss 0.695 ms
= 1.11 MiB ÷ 1.6 GiB/s）。

⇒ **兩邊瓶頸性質不同 ⇒ 任何「誰全面更好」的說法都不成立。**
⇒ 也說明對方的 2.90 %/pp 可能有一部分是非 IO 因素（待閉合：其 `slot-bank 128` 是否含 Python 開銷）。

## 6. 功能完整度 —— 我們明顯領先

| | 我們 | FlashMLX |
|---|---|---|
| MTP / speculative | ✅ 每 step 3.117 token，**off 9.82 vs on 12.62 = +28.5%** | ❌ 不支援 |
| i-quant（IQ2_S/IQ3_S） | ✅ | ❌（MLX 無此格式） |
| 生產 server | ✅ | ❌（bench 腳本） |
| oracle ceiling 方法論 | ❌ 未做（§EN-475 已出設計） | ✅ `bench_slot_bank_oracle_hits.py` |

⇒ 換過去會**直接丟掉 MTP 的 +28.5%**（§EN-474）。

---

## 7. 約束適配性 —— 這才是真正的分野

- **對方的路線**：大內存 → 高常駐 → 少 miss。在 128 GB 上簡單有效。
  ⇒ 但**在本機跑不起來**：模型 12.72 GiB，全常駐佔 16 GiB 的 79.5% ⇒ 必然進 swap
  ⇒ swap 已知致命（5301 MiB 時 base 12.57 → 4.62）。
- **我們的路線**：重尾洞察 → 小內存也能高命中（143 槽吃到 89.4%）。
  ⇒ 在 16 GB 上可行，且不佔用額外內存。

## 8. 判決

**在「expert cache / SSD 串流」這個具體能力上：我們高於 FlashMLX。**

| 維度 | 誰贏 | 差距 |
|---|---|---|
| miss 魯棒性（SSD path 效率） | **我們** | **6.6×** |
| 命中率（重尾利用） | **我們** | +6.7pp |
| 每專家位元組 | **我們** | −34%（vs 其主力 4-bit） |
| 功能完整度（MTP） | **我們** | +28.5% |
| 約束適配（16 GB 可行） | **我們** | 對方跑不起來 |
| 引擎純算力 | 平手 | 與硬件差同階 |
| **絕對 t/s** | **對方** | 3.7×（**全來自機器**） |
| 方法論（oracle ceiling） | 對方 | 我們該抄（§EN-475） |

### 一句話

> **對方的數字是 128 GB 買來的；我們的方法是 16 GB 逼出來的。
> 在同等內存約束下，我們的 expert cache 更有效率；在絕對吞吐上他們更高，但那不是演算法。**

### 互相該抄的一件事

- 他們抄我們：**靜態釘住 hot set**（對他們值 **+19%**）—— 他們目前沒有用到重尾。
- 我們抄他們：**oracle all-hit replay**（把「cb 全藏」從外推變實測，設計已於 §EN-475 完成）。

## 9. 待閉合（本篇的假設，都未驗證）

1. 對方的重尾上界借用了我們的 98.2/98.9% —— **未在其模型上實測**。
2. 對方 `k=4` vs 我們 top-8（若屬實，其每 token 讀專家量只有我們一半 ⇒ §1 的差距被放大）。
3. 其 `slot-bank 128` 的 47.1 是否含 Python 開銷 ⇒ 影響 2.90 %/pp 的純度。
4. 我們的 15.14 全常駐基線是外推（交叉驗證 15.8）。
5. 對方 UD-Q2 比 4-bit 慢的反常現象成因未明。
