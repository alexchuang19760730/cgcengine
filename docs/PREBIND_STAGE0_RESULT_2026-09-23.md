## 2. ★★ 真正的根因：U 是「每次能預測的 ids 數」的 2.4 倍

失敗**不是**因為相鄰 token 的專家選擇不相關 —— 相關性其實不錯：

```
上一個 decode 步的 8 個 ids 裡，有 5.22 個落在當前步的 union 裡
  => 命中率 5.22 / 8 = 65%（既有註解寫的「相鄰 token 70-90% 重疊」是同一個量級）
但當前步的 union 有 19.41 個專家
  => 覆蓋率 q8 = 5.22 / 19.41 = 26.9%
```

**union 是 19.41，一次只能預測 8 個 ⇒ 覆蓋率的天花板就是 8/19.41 = 41%，
而且還要打 65% 的命中折扣 ⇒ 27%。**

⇒ 樹上既有的 prev-token prefetch（`CGC_PREV_TOKEN_PREFETCH`）**本來就在這個天花板底下**
工作：它每次只帶 8 個 ids。這解釋了為什麼它一直沒有可觀的收益。

### 加寬度的邊際效益很差

| 候選寬度（實測聯集） | q | 命中數 / 19.41 | 邊際命中率 |
|---:|---:|---:|---:|
| 8.0（1 個歷史步） | 0.2690 | 5.22 | 65% |
| 10.0（2 個歷史步） | 0.2987 | 5.80 | **29%** |
| 13.5（3 個歷史步） | 0.3543 | 6.88 | **31%** |

每多買 1 個候選 id 只換到 **0.3 個命中** —— 因為第 2、3 個歷史步的專家大半落在
union 之外（它們是別的 token 的專家，而 union 已經被當前這 4 個 token 撐到 19.41）。

## 3. 要多寬才夠？（外推，以及為什麼不值得）

門檻（step −10% 兩平，實測輸入）：`sigma=0` 下 **q ≥ 0.6917**、
`sigma_hat` 下 **q ≥ 0.5791** ⇒ 需要命中 **≥ 11.24** 個，目前 6.88，還差 **4.36**。

按實測的邊際命中率外推：

| 假設邊際命中率 | 還要多少候選 | 需要總寬度 |
|---:|---:|---:|
| 30%（實測值） | +14.5 | **~28 ids/層** |
| 25% | +17.4 | ~31 ids/層 |
| 20% | +21.8 | ~35 ids/層 |

即 **約 6-7 個歷史 decode 步**的 ids 聯集，是 8 ids/層 baseline 的 **3.5-4.4 倍**。

兩個理由讓它不值得（而且是同一個方向的）：

1. **LRU 擾動**：40 層 × 28 = **1120 次 slot touch/步**，而實際需要的只有
   40 × 19.41 = **776** —— 你為了預指派去動的 slot 比真正要用的還多 44%。
   `prebind_ev.shadow_cost(28)` 說時間塞得進窗口（44.0 ms / 129.8 ms，2.95x 餘量），
   但**時間不是成本，快取污染才是**，而污染沒有被那個模型算進去。
2. **外推本身不可靠**：實測只到 3 個歷史步，往外推到 7 步假設邊際命中率不衰退，
   而它沒有理由不衰退（越遠的歷史與當前 token 越無關）。

⇒ **結論：寬度買不到 q。** 既有的 `q32`（= 歷史 3 步 ∪ draft）也救不了 ——
實測 **q32 = q24 = 0.3543**，因為 draft 在這個形狀下一次都沒收集到（`rows` 全 0）。

## 5. ★★ 相關性 sigma：只能由「逐層 res 的變異數」估

### 不能用 `clean_pct` 反解（循環論證）

本輪 q 雖然不是 0，但 probe **不改行為** ⇒ `clean_pct` 永遠是**沒有預指派**的基線，
照樣只取決於 `p_res0` 與 `sigma`。看似可以反解 —— 那會得到 1.191。
但 `clean_pct` 正是模型要預測的量 `E[r_z^U]`：**拿它配適出的 sigma 再去降門檻
== 用來放寬的數字就是放寬後要預測的數字。**

### 改用二階矩

```
res_layer = (1/U) · Σ Bern(r_z)  =>  Var[res] = Var[r_z] + E[r_z(1-r_z)]/U
run2: mean(res) = 0.9121, sd = 0.1047, var = 0.010965  (n = 1960)
      二項噪音項 E[r(1-r)]/U ≈ 0.00449（sd 0.067）— 只佔觀測 sd 的 64%
=> sigma_hat = 1.028     （prebind_ev.sigma_from_res_spread，不動點迭代 3 輪）
```

這樣 `clean_pct`（U 階矩）就從配適點變成**驗證點**：
用二階矩估出的 sigma 預測 U 階矩 = **31.0% vs 實測 36.5%（+5.5 pp，±10 pp 內 ✓）**
⇒ logistic-normal 隨機效應這個函數形式在這個資料上站得住。

| 來源 | run 1 | run 2 |
|---|---:|---:|
| 由 `clean_pct` 反解（**循環，不用來定門檻**） | 1.191 | – |
| **由逐層 res 變異數估（採用）** | **1.019** | **1.028** |

兩輪只差 0.009 —— 這個估法是可重現的。

## 7. q 的量法被推翻過一次：draft context 不能當全層預測源

第一支 log `pred_pct = 0.0%`（1880 層全部 `pred=0`）。根因不是 env 沒到、也不是層號錯：

- MTP draft graph **只跑 nextn block**，draft ctx 的 hook 只在 **`il == n_layer`** 觸發；
- 而 verify 用的 `il` 是 **0..39** ⇒ 兩邊永遠對不上；
- 實測 `rows` 分佈 = `{0: 1960}`（第二次也是全 0）。

⇒ **在這個 MTP 架構下「用 draft 預測全層」不成立。** 這同時意味著樹上既有的
`draft_prefetch_ids`（靠 draft 收集的 `[layer]` 陣列）在這個模型上是空的 ——
它的 prefetch trigger 讀到的是從未填過的 buffer。**這是既有設施的缺陷，不是 probe 的。**

### 修法（已實作、已跑出數字）

改用**時間局部性**（與既有 prev-token prefetch 同一個預測源，但不開
`CGC_PREV_TOKEN_PREFETCH` —— 那個 env 會改變行為），probe 自己維護
`prebind_p1/p2/p3/curr` 四份 buffer，`il == 0` 時旋轉：

- `cov8` = 最近 1 個 decode 步、`cov16` = 2 步、`cov24` = 3 步的 ids 聯集
- `cov32` = 上述 ∪ draft（draft 若真有就是白撿 —— 實測是 0）

另外補掉三處會讓讀數不誠實的：

1. **prefill 污染歷史**：mirror 收集加 `cgc_is_decode_graph()`，只收 decode 步；
   前 3 個 decode 步 `hist < 3`，照實排除而不是拿 prefill 的 row-0 ids 充數
   （那只會把 q 灌高）。
2. **「寬度 24」只是名義值**：多印 `w8/w16/w24/w32`（候選集合**實測**大小）與
   `hist=`（非空歷史 0..3）。實測 **w24 = 13.5** —— 相鄰步的 top-8 重疊很多，
   真正買到的寬度只有 13.5，不是 24。
   （`w24` 分佈還呈雙峰：1489 層落在 8-16、224 層落在 17-24 —— 對應「路由穩定」與
   「路由發散」兩種層。）
3. **解析器把 `clean_pct` 拿去比 `f_clean(q24)`**：probe 不改行為 ⇒ 實測值永遠是
   q=0 的基線，比值符號固定為負 ⇒ 每輪都會被判「模型不符」而吃掉 gate。
   改成比 `f_clean(q=0)`（見 §5）。
