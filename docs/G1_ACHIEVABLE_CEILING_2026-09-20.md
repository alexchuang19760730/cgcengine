# 一個**正確**設計可達的天花板：G1 的 ×1.702 與它唯一的前提（2026-09-20，零 GPU）

**這份文件不重新推導 D3。** D3 的機制、實作切點、風險與閘門已經寫在
`docs/REMAP_ROUNDTRIP_REMOVAL_PLAN_2026-09-15.md`（§4 階梯、§5 設計、§5.5 分階段、§5.6 驗證與風險、
§9.17 submit-ahead 的定位）。本檔只回答三個**目前的記錄回答不了**的問題：

1. 那個 ×1.702 裡，**一個正確設計**能吃到多少？（探針的天花板 ≠ 可交付的天花板）
2. G2／M1 對它要求什麼？
3. 「一次移除一個邊界、預期 −0.32 ms」怎麼測？

---

## 0. 一句話

**天花板 = ×1.702（44% 的步），而它可不可拿，取決於一個從未被量過的量：`slot_table` 的發布是否
在熱路徑上（前提 B）。** 在它被量出來之前，「正確設計可達多少」的正確答案是
**介於 1.0 與 1.702 之間的一個未知數**，而不是任何一個具體倍率。

## 1. 探針的天花板 ── 它是量具，不是設計

`CGC_SUBMIT_AHEAD=1`（`run_server.sh` allowlist，banner 會回報 `diag: submit_ahead=`）在 segment i 的
top-k hook **寫 remap leaf 之前**就提交 segment i+1。輸出**預期損壞**，因為 GPU 讀到的是舊的 remap。
它量到 step 169.21 → 99.39 ms（×1.702）、兩個獨立儀器一致（SUBHEAD_AHEAD 41.2% vs 區間儀器的
41.9% idle）。**⇒ 44% 的步是「等 host 寫 leaf」造成的**，這件事是可信的。

但那個 44% 是**「40 個段邊界全部被無代價地穿過」**的天花板。任何正確設計都不會免費拿到它。

## 2. 三條路，與它們各自的條件

| | 做法 | 段數 | 擋住它的東西 |
|---|---|---|---|
| **S2** | 保留分段，**不等**（流水線） | 40 | 圖裡仍有 host 寫入 ⇒ 等的是**正確性**；只有當 leaf 由 GPU 算（S1）才合法 |
| **S3** | **不分段**（`n_segs` 40 → ~1） | ~1 | 前提 B：`slot_table` 若每步都要重發布，host 寫入只是 from「per-step remap」變成「per-step table」 |
| **D0** | submit-ahead（**故意錯**） | 40 | 不可交付；只是上限量具 |

**★ 記錄裡有一個矛盾，必須指出來：** G1 的 `new_question_verdict` 說「Revised lever: **overlap the CPU's
encode with the GPU's execution** … 那是 G1 應該被指到的計畫」（= S2），而同一份樹上的
`REMAP_ROUNDTRIP_REMOVAL_PLAN` §9.17(c) 說「**S2 在 D3 下很可能是繞路** … ⇒ 建議 **S1 → S3**，S2 只作
fallback」。**兩者不可能同時是對的**，而它們的差別正是前提 B：

- 若前提 B **成立**（table 發布不在熱路徑上）⇒ 段邊界失去理由 ⇒ **S3**，而且等待自動消失（S2 繞路）。
- 若前提 B **不成立**（每步都要重發布）⇒ 段邊界仍需要 ⇒ **只能 S2**，而且它的合法化（leaf 由 GPU 算）
  已經由 S1 完成。

⇒ **決定 S2/S3 的不是設計品味，是前提 B 的一次量測。**

## 3. 前提 B：唯一那個還沒被量到的量，與它為什麼難量

**要問的是**：`cache->slot_table` 的 entry，**相鄰兩步之間有多少個改值**。
表內容每步都動 ⇒ 每步都得重發布 ⇒ 前提 B 不成立。

**為什麼現有的儀器都答不了（三個都已被記錄否證，別重踩）**：

| 儀器 | 為什麼不行 |
|---|---|
| `CGC-SLOT-TABLE` clamp 計數 | 只在 **clamp 發生**時觸發。全天 0 行只證明「沒有 clamp」，**不證明「沒有更新」** |
| `publish_slot_table` 呼叫次數 | 全部呼叫點只在 S1 remap hook 內 ⇒ **by construction**：baseline 0、S1 每個服務層 1。它量的是「機制存不存在」 |
| `LLAMA_EXPERT_CACHE_STEP_DBG` 的 `fastcold/fastuni` | 它的 block 在 **fast-path 分支內**，而 `prod25`（MTP off）實測**每步 `fast=0`** ⇒ 那條臂上**永不執行、0 行**，是死路不是零 churn |

**⇒ 儀器要放在 fast-path 分支「之外」**（§9.17(d′) 的結論）：在 `il == 1` 處把 `slot_table` 與
**上一步的快照**逐一比對，累加「改值的 entry 數」，連同步數一起輸出。

⚠️ 這是 `src/` 的改動 ⇒ 需要一次 build，而 build 會蓋掉別人正在用的 dylib（本線的規則）。
**⇒ 這是一個要排窗口的工作，不是一個可以現在做完的工作。**

⚠️ **一個只能當先驗的舊讀數**：2026-08-28 的「cold ~65% in EVERY phase ⇒ structural churn,
not a cold start」**指向「前提 B 不成立」**。但它取自**另一個配置**，所以只能當先驗。

## 4. G2／M1 對它的要求（硬閘門，缺一不可）

1. **M1/M2/M3 + M2 oracle：bit-identical。** M1 是 `row_fnv1a64` ⇒ **逐位元**。D3 是**排程**改變，
   合法的實作必須產生**同一組 slot**、**同一個求和順序**。
   - D3 的合法性來自「同 id → 同 slot → 同順序」：`slot_lookup` 必須是**純查表**（無加減、無歸約），
     這與 G4 那條被否證的 fuse（把權重乘進 K 迴圈）是**不同的**情況 —— 它可以逐位元。
   - ⚠️ 而 S1 真臂在**分段**下同 build、同 N 是 **3 輪 3 值**（§9.17(e)）⇒ **分段本身引入不確定性**，
     所以 bit-identical 這道閘門在 S3 之前**是擲骰子**。這讓 S3 的價值不只是省時間。
2. **`gap` 必須塌向 0**（`CGC-GPUTIME`）—— 這是「成功」的直接量測，不是旁證。
3. **`wait` 的下降量應 ≈ `cb + submit` + 被移掉的延遲**（`CGC-DECPROF`）。對不上就表示吃到的不是那 44%。
4. **品質不得上升為代價**：`zero_mapped_selected` / `n_fast_cold` **不得上升**。
   這是 G1 交叉詰問的結論：round trip **買的就是 routing 的新鮮度**（6.16% 的選擇在步初不在池裡，
   其中 3.79% 是 first-touch、不可預測）。分段消失之後，晚到的 fill 會退化成 **ZERO-mapping**
   ⇒ **貢獻被丟棄**。那是品質代價，必須被計數與閘門約束（G2）。

## 5. 「一次移除一個邊界、預期 −0.32 ms」怎麼測

理由：G1 的機制是 `gap_L = 1.00 × cb_{L−1} + 0.29–0.35 ms`（r +0.94…+0.999，L0 的 gap 恆為 0.000）。
**兩成分可分辨**：斜率 1.00 的那一項是 host 的 top-k hook；常數 0.29–0.35 ms 是**每個邊界的
submit+launch 殘留**。第二項**與邊界數線性**，所以它可以一個邊界一個邊界地驗：

1. **基線**：一個暖 run，讀**步表頭**的 `gap_sum` **中位數**（不是逐層中位數的和 —— 同一批 184 步上
   兩者差 39%：21.43 vs 34.76 ms），以及 `segs=41`。
2. **移除一個邊界**（一個實驗臂，只改這一個）：預期 `gap_sum` 中位數 **−0.32 ms**，
   `total` 同步下降同一個量，**`union` 不動**。
3. **判準**：一次 −0.32 ms 在噪音裡 ⇒ 需要**多個**邊界才能判。**這正是「一次一個」的用意** ——
   它把「39 × 0.32 = 12.5 ms 的地板」變成可以**分次累積驗證**的線性關係，而不是一次要跳到 12.5 ms。
   ⚠️ 用 `union_floor.py` 先確認那個 run 的 3SE 小於 0.32/中位數（對 n≈180 的暖 run 是 8.0%，
   **遠大於** 0.32/132 = 0.24% ⇒ **單一層的效應量測不出來**）。⇒ **要一次移除一批，或改用
   配對（同一 run 內 A/B 交替）**。這條在動手前就要算，否則會量到一堆「沒有差」。
4. **`−0.32` 的來源**：`from` 41 段 → 1 段是 39 個邊界 × 0.32 ≈ **12.5 ms**，而
   `reachable_floor` 已經證明：**`gap_sum/total <= 5%` 在 40 段的步上不可達**（地板 12.5 ms ＞
   5% of 139.46 = 6.97 ms）。可達的重述是 **(a) `cb_sum/total`** 與 **(b) 邊界數**。

## 6. 這份文件**不能**支持的

1. ❌「正確設計可達 ×1.702」—— 未知。介於 1.0 與 1.702 之間，取決於前提 B。
2. ❌「S2 是對的路」或「S3 是對的路」—— **記錄裡兩者互相矛盾**，而決定它們的量還沒量。
3. ❌「D3 收段會慢 ~20×」—— §9.17(g) 已指名的陷阱：`CGC_OA_ASYNC=0` 的 0.72 t/s 是
   **40 個 split ＋ 序列化 dispatcher**，D3 收段是 **~1 個 split**。那是調度策略的價值，不是分段的價值。
4. ❌「S1 沒用」—— S1 是 **D3 的必要前置**（leaf 由 GPU 算），它「一個 host 步驟都沒省」正是因為
   分段還在。這與「S1 無效」不同。
5. ❌「單層移除量得出來」—— 見 §5.3，3SE 8.0% ≫ 單層效應 0.24%。
