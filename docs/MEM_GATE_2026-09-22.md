# 記憶體／swap 門禁（2026-09-22，§EN-421）

## 1. 為什麼要有這一道

2026-09-22 01:0x，封版數字 **12.57 t/s** 的交付 cell 連續回來 **8.36 / 8.59 t/s**（−34%），
而當時**所有既有的門禁都是綠的**：

| 舊門禁 | 當時讀數 | 結論 |
|---|---|---|
| thermal（`notifyutil` thermalpressurelevel） | **NOMINAL** | 通過 |
| 沒有別的 session 在量測 | `others()` 空 | 通過 |
| `usable_pct >= 30%` | 起跑前 ≥30% | 通過 |

真因在記憶體，而上面三道一道都看不到：

```
vm.swapusage:        used 6.7–6.8 GiB / 8 GiB total   (~83%)
compressor:          730 917 pages stored  (≈12 GB 壓縮進 1.87 GB)
usable = free+inactive+speculative:  1.26 GiB  (7.9% of 16 GB)
```

expert cache pool 要 8 GiB，model 的 dense 部分也要常駐，兩個加起來跟 page cache／swap 搶
同一個 16 GB ⇒ **填池的每一次 miss 都可能踩到 swap**。這不是「排程寫得笨」，是箱子上沒有地方放。

同一批 run 的**臂內離散**也對得上：一個臂的三個 rep 是 **7.04 / 10.92 / 7.80 t/s（55% 跨度）**，
而封版時期交付 cell 的臂內 CV 只有 7.88%。離散度自己就是症狀。

## 2. `purge` 到底做了什麼（本次實測，兩條都重要）

| | purge 前 | purge 後 |
|---|---:|---:|
| Pages free | 3 553（0.06 GB） | **447 613（7.3 GB）** |
| usable（free+inactive+spec） | 1.26 GB（7.9%） | **7.77–8.42 GB（48.6–52.6%）** |
| swap used | 6 730 MiB | **6 490 MiB（幾乎不動）** |

- **① purge 對「可用記憶體」非常有效**（7.3 GB 回來）。
- **② purge 完全不減 swap_used。** 換出的頁只有在其持有者 fault 回來或結束時才會釋放
  ⇒ **swap_used 是黏的（sticky）**：不關掉持有它的 app（或重開機），它會一直停在 6.5–6.8 GB。
  ⇒ 門禁**不能**寫成「swap_used == 0」，那會永久拒絕；誠實的線是「swap 還沒被用光」。

## 3. 門禁設計（`scripts/check/window_sentinel.py`）

`mem_gate()` 回傳 `(ok, why, detail)`；`mem_report(detail)` 印一行處方。硬拒絕條件：

| 條件 | 預設門檻 | 為什麼是這個數 |
|---|---|---|
| `usable_gib`（free+inactive+speculative） | **≥ 8.0 GiB** | pool 8 GiB 要落地，dense 也要常駐；低於此一定會把別人擠去 swap |
| `swap_used_mib` | **≤ 6144 MiB**（8 GB 的 0.75） | 「還沒用光」＝還有緩衝；用光之後任何新的壓力都直接變 thrash |
| 單一 app RSS | **≤ 4 GiB** | 桌面 app 是 operator 關得掉的東西，不是我們能修的 |

- **`>= 1 GiB` 的 app 只報告、不拒絕**（本機最大戶是 WorkBuddy Helper(Renderer) 2.7–2.8 GiB，
  而那是我們自己 ⇒ 拿它當拒絕條件會把自己鎖死）。
- **門禁不試著自己修**：關 app 和 `purge` 都是 operator 的動作，腳本只把 pid／名字列出來。
- CLI：`--swap-max-mib` / `--usable-min-gib` / `--purge`。

### `purge` 需要 root，而 agent 沙箱拿不到

| 嘗試 | 結果 |
|---|---|
| `/usr/sbin/purge` | `Unable to purge disk buffers: Operation not permitted` |
| `sudo -n purge` | `sudo: a password is required` |
| `sudo purge`（互動） | 工具殼沒有 TTY（`tty` = not a tty），`no tty present`，密碼傳不到人 |
| **`osascript -e 'do shell script "/usr/sbin/purge" with administrator privileges'`** | ✅ **成功**（彈 macOS 授權對話框，本次用它跑過一次） |

⇒ `window_sentinel.py --purge` 走 osascript 這條；其餘情況請 operator 在自己的終端機敲 `sudo purge`。

## 4. 流程（已寫進 `MEMORY_HYGIENE.md`）

1. **關掉門禁點名的 app**（它會印 pid + 名字 + RSS）。
2. **`sudo purge`**（或 `python3 scripts/check/window_sentinel.py --purge` 彈框）。
3. **重跑門禁，OK 才起跑。**

swap 清不掉時只有兩條路：**重開機**，或用 `--swap-max-mib 8192` 覆寫 —— 但要接受數字偏低
（這次 8.36／8.59 就是在那種狀態下量出來的）。
