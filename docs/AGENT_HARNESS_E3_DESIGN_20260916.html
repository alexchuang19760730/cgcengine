一句話

E3 的題目是「注入 lesson 有沒有改善決策品質，而且可重現」。這一輪沒有跑那個實驗 —— 它需要的模型端點會干擾另一條線正在進行的量測。這一輪做的是讓那個實驗一旦能跑， 它的輸出就不可辯駁：注入範圍變成一個明確的參數（因為計畫寫的「8 條」與它自己的 §4.3 列出的十條不一致）、--reps 預設 3 且交錯輪轉（因為單次採樣證明不了「可重現」）、 臂內不一致的題目其跨臂判斷一律作廢、以及一份 33 項的離線自測 —— 其中最重要的一對是「同一個假模型、同一組題目，只換注入範圍，一次必須答『相同』、 一次必須答『不同』」。

一個刻意的非改動

「8 條」這個數字沒有被我改成 10。§4.3 的表格列了十條、§6.3 與 §11 寫「8 條」—— 這是計畫的內部不一致，處置方式是在兩處都加註記說明它不一致、以及「那 8 條」的可執行定義 是什麼，而不是替它選一個數字。選一個數字會讓一個未決的編輯決定看起來像既成事實。

2. 典籍說「8 條」，而典籍自己有十條

PLAN §9 的 E3 原始驗收句是「閉環：round1（無 lesson）vs round2（8 條 lesson）在同一個待答問題上」。 那句裡的 8 出現在三個地方，而其中一個地方已經不再是 8：

位置寫什麼現在的實況
§6.3「注入今天定稿的 8 條 lesson」—
§9 的 E3 欄「round2（8 條 lesson）」—
§11「§4.3 那 8 條 lesson 直接搬成憲章條文」 §4.3 的表格現在列了 10 列

所以「那 8 條」需要一個可執行的定義。lessons.jsonl 是 append-only 的， 它的檔案順序就是那些 lesson 被寫下的先後；而它的前八筆正好是 §4.3 的前八列：

  scope: first:8 -- 8 lessons, in file order (the k-th is eng-bound-0001)
    ids: eng-mh-0003, eng-lf-0007, eng-diag-0011, eng-diag-0012, eng-gate-0002,
         eng-src-0005, eng-src-0006, eng-bound-0001

這八筆橫跨六個 class，所以依 id 排序會選到一組不同的集合——這是為什麼 first:k 取的是檔案順序而不是序號順序，也為什麼這件事在程式裡留了註解。

3. 注入範圍是一個參數，不是一個常數

scope注入什麼時候用
all（預設）全部 live lesson問「harness 現在知道什麼」
none空陰性對照：D 臂的 prompt 必須與 C 臂位元組相同
first:<k>lessons.jsonl 的前 k 筆PLAN §6.3 的實驗臂
class:<abbr>單一 class隔離某一類規訓的影響
ids:<path>明確清單（一行一個，# 可註解）逐條列舉，可重現性最高

為什麼它不能是寫死的

注入全部時，一個觀察到的改善可能來自任何一條 —— 因果被抹平。注入 8 條時與計畫一致， 但丟掉後來寫的近百條。兩者都有道理，所以它是一個要明確做的決定； 腳本偷偷選一個，就把一個決定變成一個習慣。

3.1 選取用權威，內容用投影

這兩個來源是分開的，而且是刻意的：id 從 traces/lessons.jsonl 選（那是權威）， 文字從 harness_engine/memories/engine/ 取（那是注入的形態）。 中間的接縫是「選到的 id 必須有對應的 memory 檔」，而它是一個硬錯誤：

5 selected lesson(s) have no memory file under
  agent_harness/engine_loop/harness_engine/memories/engine:
  ['eng-diag-0024', 'eng-diag-0025', 'eng-src-0014', 'eng-mh-0042', 'eng-diag-0026']
  Run `harness_engine/build_memories.py` first. Refusing to run an arm that
  silently drops lessons: a filter out of sync with the projection is
  indistinguishable from 'those lessons do not apply'.

3.2 這個守衛在真實情況下被觸發了（不是測試造的）

上面那段輸出不是設計文件裡的範例。寫這一輪的時候，另一個 session 在 19:54:58 往 traces/lessons.jsonl 追加了 5 筆 lesson（eng-diag-0024、 eng-diag-0025、eng-diag-0026、eng-src-0014、eng-mh-0042， 內容是他們那條線的 Metal 診斷），而 memories/ 投影還是 106 檔。 於是預設的 all 拒跑了。

檢查結果為什麼這是有用的訊息
那 5 筆是否合法通過 validate.py：111 records，applies_to 無懸空 合法的 record ⇒ 是權威前進，不是壞資料
build_memories.py --check報 5 個 drift 並給出重生指令 投影落後於權威，而這兩份檢查工具都各自說得出來
重生後111 檔，--check OK，all 恢復 訊息是可執行的：照著跑就好
first:8不受影響 明確 id 選取對權威前進是免疫的——它問的是「那 8 條」，不隨倉庫長大而移動

這一節真正的重點

如果守衛是「靜默跳過缺檔的 id」，那麼這一輪會照常跑完、照常產出一份報告， 而那份報告的 D 臂少了 5 條 lesson —— 它與正確的 D 臂在輸出上長得一模一樣。 守衛的價值不在於它擋下了什麼，而在於它讓「少注入幾條」無法偽裝成「本來就只有這些」。

4. 「可重現」的實作：--reps 與臂內一致性

PLAN §9 的驗收寫的是「至少 1 條 lesson 被證明改善且可重現」。 單次採樣做不到後半句：兩個臂各答一次而答案不同，與「這個差異是雜訊」在觀察上無法區分。 所以預設是每個（題, 臂）呼叫 3 次 —— 這與 eng-mh-0003 對吞吐數字要求的 「交錯 ≥3 輪」是同一個標準，只是把它用在量 harness 自己的那個儀器上。

機制防的是什麼
交錯（題／臂輪流，不是每個臂連續跑完） 與序列位置相關的漂移不會整個落在同一個臂上
輪轉（每個 rep 的臂序往前移一位） 「總是最先被問」或「總是最後被問」不再是任何一個臂的固有性質
臂內一致性（同臂的 reps 是否給同一答案） 雜訊穿著效果的標籤：一個臂自己前後不一致時，跨臂的差異不是效果
  arm_order_by_rep         =        <-- manifest.json 記下實際順序
      rep1: A_preD6 -> B_postD6 -> C_head -> D_head_mem
      rep2: B_postD6 -> C_head -> D_head_mem -> A_preD6
      rep3: C_head -> D_head_mem -> A_preD6 -> B_postD6

而當某個臂自己不一致時，compare.json 不是把它記成「不同」，而是記成 不能比：

{
  "arm_stability": { "A_preD6": {"n": 3, "distinct": 3, "stable": false}, ... },
  "comparable": false,
  "note": "至少一個臂自己前後不一致 ⇒ 這一題的跨臂判斷無效（先看是哪個臂、
           以及不一致的是不是『承重點』本身）",
  "A_vs_B_identical": null,          <-- null，不是 false
  "A_vs_B_verdict": "無法判斷（臂內不穩定）"
}

null 與 false 的差別是這一節的全部

「不能比」與「比過了，相同」必須長得不同。把前者記成 false， 就是在一個沒有資訊的題目上產生一個看起來有資訊的欄位 —— 而那正是這整個 E3 要防的錯。

5. 自測：33 項，其中最重要的是「儀器必須說得出沒有差異」

closed_loop_selftest.py 不碰真模型、也不碰真實的投影目錄或輸出目錄。

5.1 核心的那一對

同一個假模型、同一組題目，只換注入範圍：

C. 陰性對照：scope=none ⇒ C 與 D 的 prompt 位元組相同 ⇒ 必須回報「相同」
  [ok] C vs D 相同（儀器說得出『沒有差異』）   verdict=注入 lesson 在這一題上沒有改變答案
  [ok] 同一輪裡 A vs B 仍不同 ⇒ 不是全盤說『相同』的假順從

D. 陽性：scope=first:8 ⇒ D 帶著 lesson ⇒ 必須回報「不同」
  [ok] C vs D 不同（lesson 真的進了 prompt）   verdict=注入 lesson 改變了這一題的答案
  [ok] 四臂各自穩定 ⇒ comparable=true

一個只會回答「不同」的比較器不叫比較器 —— 它是一個同意你的裝置。 C 那一組證明了它有能力說出「沒有差異」，D 那一組證明了它不會對所有東西都說「沒有差異」。

5.2 假模型為什麼用 sha256 當答案

假模型的答案是 sha256(prompt)[:16]：確定性、對 prompt 的每一個位元組敏感， 而且 —— 重點 —— 與 prompt 的內容無關。一個「看到某段文字就回某個答案」的假模型， 會在有人編輯那段文字的當天開始說謊，而且會繼續通過測試。雜湊沒有能力在乎文字的意思， 它只能報告位元組有沒有變 —— 那正是這些檢查要問的問題。

6. 兩個我自己造成的 bug，以及它們為什麼值得寫下來

自測第一次跑出 5 個 FAIL，而它們的症狀互相矛盾：該拒跑的沒拒跑、該成功的沒成功。

症狀根因
守衛沒有拒跑 同一個 bug，在兩處：Path.relative_to(REPO) 對 repo 之外的路徑會拋例外。而自測為了不污染真實目錄， 正是把投影目錄與輸出目錄重導到 repo 外的暫存目錄。
該成功的執行反而 rc=1（但產物是對的）

值得記下來的形狀

第二個 bug 崩在 print(f" out: {out.relative_to(REPO)}") —— 那是 執行完所有產物之後的一行裝飾性輸出。產物完全正確，程式卻以 rc=1 結束。

第一個 bug 更糟：守衛確實偵測到了缺檔，它是在渲染自己的訊息時崩的。所以從外面看， 「守衛擋下了壞輸入」與「這支程式有 bug」是同一個事件：一個 traceback ＋ 一個非零結束碼。

一個訊息送不出去的守衛不是守衛。而錯誤路徑之所以會壞，正是因為它平常不會被執行 —— 這與 E2 那次「validate.py 只被跑在正確輸入上」是同一個形狀。

修法是 rel(p)：在 repo 內就顯示相對路徑，不在就顯示絕對路徑。 修正後 33/33 全過。

8. 誠實邊界：E3 本體沒有被結清

不主張什麼

  • E3 本體未結清。本文件交付的是執行器與實驗設計。PLAN §9 的驗收句是 「至少 1 條 lesson 被證明改善且可重現」—— 沒有一條 lesson 被證明任何事， 因為模型半沒有跑。
  • 未跑的理由是具體的：本機沒有模型端點（1234/1235/8080/11434/8000/5000/9000 全無回應）。llama-server 與 13.6 GB 的模型都在，所以技術上可以起 —— 但另一個 session 當時正在改 ggml-metal-ops.{cpp,h} 並重建 dylib， 而他們的 prefill/decode 量測對 GPU 時脈極敏感。為了結清一條欠帳而弄壞另一條線的 資料不算結清。
  • D6 的欠帳也仍然開著（同一個 blocker）：A vs B 需要同一個模型端點。 措辭已在 CONVENTIONS.md §E 與 D6 段、以及 PLAN §9 的 E2 欄改成 「預期改變不到」（而非「改變不到」）。
  • 33 項自測只證明機械。它對「lesson 有沒有用」沒有任何主張 —— 它連一次真實模型都沒看過。
  • --reps 3 不是一個統計主張，它是「能否區分穩定與不穩定」的下限。 需要信賴區間時要調高，而那會是另一個決定。

8.1 一個競態，以及它如何自行消解

動筆的時候，另一個 session 在 19:54:58 往 traces/lessons.jsonl 追加了 5 筆 lesson（見 §3.2 —— 那正是守衛被觸發的原因）。當時它們還沒被提交，所以重生 harness_engine/memories/engine/ 會把另一個 session 的工作區位元組寫進我的 commit。 別人的資料不該看起來像我的資料，所以那一版白皮書把它寫成一節「必須揭露的副作用」。

收尾前再查一次，情況變了：他們在 cd91aab01 把同一組 5 筆提交了，而那個 commit 的訊息自己寫著「本 commit 的那 5 條 lesson 就是它（build_memories.py）的輸入」。 也就是說他們刻意只 append 權威，把衍生物的重生留給這條線。於是：

收尾前的檢查結果
git show HEAD:…/lessons.jsonl | wc -l111
git status 裡的 scripts/ 與 src/不見了（他們 commit 掉了）
git diff HEAD -- …/lessons.jsonl空 ⇒ 重生是對已提交的權威做的
我的 commit 將包含只有我自己改的檔案 ＋ 5 個衍生物（其權威已在 HEAD 裡）

所以那一節本來會是一個副作用，結果是一個被正確分工吸收掉的競態。 但讓它變成後者的不是運氣：動筆前查一次、收尾前再查一次。只查第一次，這份文件就會留下 一段在收尾時已經不成立的話 —— 而它會讀起來像事實。
