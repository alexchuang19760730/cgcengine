2.4 處置：兩層，而且其中一半沒有解

  • 正常 import 的 entry：shim 把自己所在的目錄放進 sys.path、逐一 re-export， 並在最後把自己的類別換成一個 __setattr__ 會轉發到「定義該名字的模組」的 ModuleType 子類。於是 km.pool_geometry = x 仍然改到 knifeedge.feasibility.pool_geometry。
  • 路徑載入（spec_from_file_location）：Python 不把那種模組放進 sys.modules，所以沒有任何物件回指的辦法 ⇒ 攔不到。 那三支離線自測用的就是這個方式，它們的正解是把子模組綁在 entry 上、改打 km.feasibility.pool_geometry（各 5 處與 1 處）。

改完之後的判準是逐字元：兩支離線自測在等價環境（git archive HEAD scripts/check ＋ models／src 符號連結）下，與搬遷前的輸出逐行相同， 兩邊都是 ALL PASS。5 支 CLI 呼叫端 --help 全部 rc=0。

4. E4 item 1：log 政策 —— 變成斷言之後的第一個發現

政策原文寫在三個地方：PLAN §8 的段落、.gitignore:419-425 的 dated 註解、 以及幾支腳本的行為。它從未被機檢過。而它的一句話是： 「Backup/cgc_logs 原文不進 repo」。

把政策抽成 shared/log_policy.json ＋ check_log_policy.py 之後， 第一次執行就抓到： 
Backup/cgc_logs 底下有 12 個檔案違反政策：['…/p25-gputime_llama_server_20260916_201242.log', …]
grandfathered 清單裡有 2 筆已經不在版控裡了 —— 把過期的例外刪掉（這是修好清單之後才出現的第二類）
那 12 筆共 5,831,279 bytes（10 個 ~670 KB 的 llama-server 原文 ＋ 2 個小檔）， 而 git grep -l <檔名> -- docs/ '*.md' 的引用數是 0。

為什麼是「登記」而不是「移出」：它們是另一條線的量測證據，移出等於刪掉別人的東西 （而且如果他們的白皮書引用著它，引用會懸空）。所以處置是把每一筆寫進 grandfathered：逐筆印出、附 owner 與大小，並且多一筆就紅。 登記不是豁免 —— 它的功能是把「沉默的違規」換成「看得見的例外」。

反向對照（這一條決定了檢查器有沒有判別力）：Backup/cgc_logs 底下另外 22 個檔案（118 KB 的 arms.json／*.tsv／req2retest*.txt） 是衍生摘要不是原文，政策不禁它們。如果檢查器只會「檔數變多就紅」， 它會把這 22 筆報成違反 —— 而那時「12 筆真違反」就被 22 筆假陽性稀釋掉了。 處置是把「原文」操作化成兩條可量測的：(a) 這個路徑下不得有版控中的 *.log； (b) 不得有單一版控檔超過 256 KB（＝ pack 上限）。

6. 誠實邊界（不主張什麼）

  • 路徑載入時的屬性寫入攔不到。 拆分的替換契約只在「模組被正常 import」時成立； spec_from_file_location 載入的 entry 不在 sys.modules 裡， Python 沒有給任何回指的辦法。那個情境的正解是 km.<module>.<name>。 不把它講成「契約保住了」（lesson eng-src-0017）。
  • 12 筆 .log 只有登記、沒有移出。 它們仍在版控裡、仍佔 5.6 MB。
  • 11 個新模組不在 MANIFEST.jsonl 裡（index_assets.py 的 glob 只掃 scripts/check/*，非遞迴）。它們的完整性由 check_module_split.py 負責， 不由索引負責 —— 這是「綠燈與沒被檢查長得一樣」的另一個實例，寫在這裡以便下一個人知道要問哪一支。
  • 沒有一項是起 server 驗的。 拆分的等價證明全部離線；check_log_policy --privacy 只解壓並掃描 pack，不執行任何量測。行為面（D6 欠帳與 E3 本體）仍缺一個乾淨的窗，見 .workbuddy/memory/2026-09-17.md §Z7 的三個當下量到的理由。
  • 目錄裡兩個既有小瑕疵沒有動（不是我的檔）：knifeedge/host.py:223 承接了一條 既有的 SyntaxWarning: invalid escape sequence '\S'（原文在 knifeedge_matrix.py:2134，逐位元組搬過來，位置隨程式碼移動）； 以及 MIN_CAP = 6 在原檔裡被連著同一段註解重複定義兩次（L424／L432）， 拆分保留兩份 —— 拆分的目標是搬運，不是順手清理。
