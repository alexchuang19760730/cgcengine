MTP on 如何把固定成本「攤薄」

加速比 S = (1 + a·k) / (1 + m·k)　｜　a=draft接受率、k=draft長度、m=每多驗一個token的邊際成本
MTP OFF（現狀）
每輪 = 1 次 target 前向
產出 1 token　→ 固定成本無攤薄
11.49 t/s
MTP ON（今天 a=0.44）
每輪 = 1 次 verify 批次 + 便宜 draft（19%）
產出 L=1+a·k ≈ 2.31 token
~13.7 t/s（S=1.19）
MTP ON（歷史 a=0.98）
同一條 draft、幾乎全中
產出 L≈3.91 token
~25 t/s（S=2.0）
攤薄槓桿（按 upside 排序）
槓桿 機制 算術 判定
① 拉高接受率 a 同一輪 verify 成本、中更多 token a .444→.977 ⇒ S 1.19→2.0 ★最大、查 regression
② k 按 m 選 k 大 L 上限高、draft 鏈線性變貴 server m=.32 ⇒ k=3 贏 看 mean_len 非 a
③ 降邊際 m verify 多 token 的 union/頻寬稅 固定 a 要 S=2 需 m≤.055（−83%） 被低效頻寬鎖死
④ draft head 成本 T=1 自迴歸鏈（19%）、不可批次 更便宜 head / k 調小 次要
關鍵結論：MTP 的攤薄倍數幾乎完全由 a（接受率）決定，不在 verify kernel（verify 已批次、每輪就一次）。 同一模型歷史實測 a=0.982 / mean len 3.91、今天 a=0.44 / 2.31——這是一條 regression / 配置線索， 已知嫌疑：draft 走 greedy、target 走 temp 0.4 採樣，兩者分布不一致（a 雙峰、對 prompt/temp 強敏感）。 把 a 拉回 .97 ⇒ 23–25；拉不回 ⇒ MTP on 現實上界就是 ~14（+19%）。
