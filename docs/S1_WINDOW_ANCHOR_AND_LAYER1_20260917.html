S1 定位：窗口錨點缺陷與 layer 1 的 MoE block

2026-09-17 00:05 · 引擎層 · 兩臂 p25-gputime（host leaf）vs p25-slotgpu（S1 GPU table） · 每輪兩臂各跑兩次（同臂對照為強制前提）

本輪的結論會讓先前的結論作廢。 09-16 那七輪（r1–r4 及 r3c/r3d/r3e）所報的「第一個分歧」 全部不可引用——它們同時踩了兩個盲點，而第三個盲點讓其中一輪連被設計來回答的那一格都沒讀到。 作廢的是定位，不是引擎：每一輪的讀數對它自己的窗口都是真的，問題出在窗口不是量測。

1. 三個儀器缺陷（都已修，都有判準）

1.1 32 詞窗口恆從 element 0 起算 ⇒ 不同節點讀到不同 token

ggml 張量是 ne0 最快，所以「前 32 個 element」的意思取決於張量形狀。實測幾何（T=8）：

節點ne形狀head 窗口實際覆蓋
conv_input-N90112(K-1+T, 8192) = (11, 8192)全部 11 行（state 3 行 + 8 個 token 的 qkv）
conv_output_raw-N65536(8192, T)只有 token 0 的 channel 0–31
attn_norm-N／z-N／gate-N／linear_attn_out-N16384(2048, T)只有 token 0

⇒ r1–r4 的每一個 “SAME” 都是「token 0 相同」，而 token 0 是那次 pass 裡最舊、 資訊量最低的 token；只有 conv_input 因為 ne0 = K−1+T < 32 而跨全部 token。 「dense 投影全同、只有 conv 輸入不同」不是矛盾，是兩個不同的窗口。

修法：內核本來就有 n_skip（恆為 0）。新增 CGC_TENSOR_CAPTURE_TAIL=1 ⇒ n_skip = ne − n，把窗口錨到張量尾端（＝最新的 token）。dump 增加 off= 記錄錨點； 分析器 --windows 先印 ne/off。讀任何 SAME/DIFF 之前先跑 --windows。

1.2 --upto 24 是為了避開偽影，結果變成盲點

分析器新增的 --decode-only 由 ne 自校準推導階段 （per-graph min(ne) ÷ 全程 min(ne)，不需要任何幾何常數）。它一跑就給出階段序列：

graph01–23–272829–3031–35
T12828241（唯一的 decode）

⇒ --upto 24 採的是 graph 1..23，100% prefill。 通則：一個用來避開偽影的旗標，自己會變成盲點；階段要量出來，不能假設。

1.3 dst_filter[256] 靜默截斷節點清單

23 個節點的清單是 312 字元，而 snprintf 的額度是 256 ⇒ 只進去 19 個， 第 20 個 attn_residual-2 被切在名字中間（,attn_residu）。 丟掉的四個裡有 ffn_moe_logits_raw-2——正是那一輪要讀的那一格。 而 r5 仍然印出一張完整、合理、毫無異狀的 19 列表。

修法：CGC_DST_FILTER_MAX = 2048、截斷改為 WARNING（判準是 snprintf 的回傳值 ≥ 緩衝大小，原本被丟棄）、init 時印出生效清單。 分析器也有同一個病（只列「出現過的名字」⇒ 被丟掉的隱形），已改成以 CHAIN 為種子並明確列出 從未捕獲的名字。

影響範圍有界：r4 的清單是 197 字元（15 名全進），r3c/r3d/r3e 更短 ⇒ 只有 r5 受此污染。

2. 換掉窗口：全張量摘要

窗口無論錨在頭或尾都只涵蓋 32 個元素，而每個節點的 (token, channel) 座標不同。 實測同一個張量的兩個窗口給出相反答案（conv_input-2：head 說 DIFF@1、tail 說 never） ⇒ 兩者都不是量測。

新增 CGC_TENSOR_CAPTURE_HASH=1：內核走完整個張量，寫 4 個字

[sum, xor, 加權和(權重 = index+1), 元素數]

  • 加權和是必要的：純 sum 看不見置換，而「不同 gather 順序造成的置換」正是這個 fork 被懷疑的東西。
  • 元素數是必要的：形狀改變不能冒充相同張量。這也讓「兩臂形狀是否一致」變成可讀的一格。
  • r.off = −1 標記「這列是摘要、不是窗口」；分析器印成 DIGEST / WHOLE TENSOR。
  • 化簡用 threadgroup 記憶體的固定樹（32 lanes），不用 simd intrinsic ⇒ 不依賴 Apple 的 simdgroup 寬度。

判準：DIFF 是結論性的；SAME 是強證據而非證明（補償性的多重集改變在原理上可碰撞） ⇒ 述句只能是「全張量上找不到差異」。

3. 結果（r7：36 名、全張量摘要、兩臂 × 2）

儀器前提已過：同臂對照全部 never、ids 全 120S/0D； 逐圖「元素數」兩臂完全相同 ⇒ 差異是內容，不是形狀。 （.metal 的改動另經確認：源碼以 autogenerated/ggml-metal-embed.s 嵌入， 判準是嵌入 .s.o 的 mtime ≥ 源檔 mtime。）

分段陷阱（判讀前必讀）

段界是 ffn_moe_gate-1，所以段 i ＝ {pass P：層 1 的 MoE 出口起 → 層 2..40} ＋ {pass P+1：層 0 ＋ 層 1 的 attention 到 router}。 ffn_moe_out-1／l_out-1 屬 pass P， attn_norm-1…ffn_moe_logits_raw-1 屬 pass P+1。 「同一 pass」的判讀靠段 0（21 列、全 SAME ＝ pass 0 的層 0 ＋ 層 1 attention）。不要同段當同一 pass。

4. 未解與下一步

  1. 摘要看不到幅度。 ffn_moe_out-1 全張量不同，但「差多少」未知。 下一步用現有窗口模式（TAIL=0/1、WORDS=32）取實際數值比對——零改碼。
  2. layer 1 的 MoE 內部未掛。 ffn_moe_gate/up/down-* 這些名字從未出現 （推測是 view 或被融合吸收）；要分清「gather 的權重不同」與「gather 之後的合成不同」，得先讓它們可讀。
  3. decode 段（graph 31–35）現在 36 個節點全 DIFF，主因是 token 流已分叉 ⇒ decode 的定位 必須在 token 流分叉之前的段上做（即 graph 1–30），這與 prefill 是同一個問題。
