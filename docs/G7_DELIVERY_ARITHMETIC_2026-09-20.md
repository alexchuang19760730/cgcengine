# G7 的交付算術：13.6 → 25 t/s 的那 1.84×（2026-09-20，零 GPU）

G7 是本專案的成功判準：`decode_tps_median >= 25`。這份文件把它的**當前值**與**缺口**算出來，
並指出兩個輸入必須一起讀才成立。

## 0. 三個數字（全部同一次 run，02:30）

| 來源 | 讀數 |
|---|---|
| `Backup/cgc_logs/joint_step_accept_g6.json`（arm `nail`，mtp=1，temp 0.4，door=chat，k=3，pool 8 GiB，8 prompts） | **`mean_len`（引擎中位）3.375**、accept（引擎中位）0.7976；8 筆逐 task 的 mean_len 介於 2.41–4.0 |
| `Backup/cgc_logs/llama_server_20260920_023021.log`（同一輪） | `ntok=4`、n=107 完整步，**step（total 中位）247.98 ms** |
| ⇒ **`t/s = 3.375 / 0.24798`** | **13.61 t/s** |

⚠️ 第三列不是「又一個數字」——它是**唯一合法**的讀法。mean_len 與 step **必須來自同一個配置**
（`scripts/check/mtp_ruler.py` 存在的理由就是它們被分開報過兩次）。所以 G7 的 `from` 也在下面被更正。

## 1. G7 的 `from` 是**退役儀器**上的數

- `12.62` 屬 **HTTP／`llama-speculative-simple`**（`docs/MTP_ABBA_RECHECK_2026-09-18.md:12`
  自己寫的），而 G7 的 `instrument` 欄寫的是 `prod_matrix.py (llama-bench, BOTH axes)`。
  **⇒ 這個閘門的成功判準引用了它自己聲明不用的那台儀器的基準。**
- 落地儀器上的記錄值是 **10.78–10.98**。⇒ 需要的倍率不是 25/12.62 = **1.98×**，而是
  **2.28–2.32×**。
- 而 `12.62` 本身**既沒有複現也沒有被證偽**：它與 10.x 的 21% 差異落在這台機器量到的環境噪音內
  （同文件 §4：兩條 MTP-off 臂，**負載 128,920 請求相同、build 相同**，t/s 卻是 **7.89 vs 9.62**）。
  ⇒ 用它當基準，等於把一個測不出來的差當成起點。

## 2. 缺口的**全部**在 step，不在 mean_len

用**同一輪**的配對（mean_len 3.375、step 247.98 ms）算「要 25 t/s 需要什麼」：

| 假設 | step | 需要的 mean_len | 現況 |
|---|---:|---:|---|
| 現況 | 247.98 ms | **6.20** | 差很遠 |
| G1 的天花板**按比例**套上去（×1.702） | 145.70 ms | **3.64** | 差 **+7.9%** |
| 要 mean_len 3.375 就夠 | **≤ 135.0 ms**（×1.837） | 3.375 | 差 **×1.10** |

⇒ **兩個獨立結論**：

1. **G6 的那一半看起來已經夠了，但「夠」是相對於 *G1 落地之後* 的門檻。** G6 的 `to` 是
   `>= 2.485 if G1 lands (99.4 ms), else >= 3.479`。實測 **3.375** ⇒ 對 99.4 ms 的門檻**有餘**，
   對 E2b 的 139.16 ms 門檻（3.479）**差 3%**，對現在的 247.98 ms 門檻（6.20）**差很遠**。
   ⚠️ **而 3.375 與 `from` 的 2.40 不可比**：G6 自己的 `measurement_preconditions` 記著 `from`
   是**貪婪**（歷史 `mtp_accept_ab*.json` 連 `temp` 欄都沒有）、**單一 prompt**（同一個請求四次）、
   且在**負載下的一個 chat turn**。⇒ 這是一個**讀數**，判決權在 G6 的 owner（line S）。
2. **即使 G1 的天花板完全可交付（×1.702），G7 仍然差 1.8 t/s。** 23.16 t/s 不是 25。
   補上它的方式有兩個，而兩者都還沒被做過：
   - **+7.9% 的 mean_len**（3.375 → 3.64，即 k=3 下 accept 0.7917 → 0.88）；
   - 或**更大的 step 削減**（×1.837 而非 ×1.702）。

## 3. 而「×1.702 可交付」本身還沒成立

`docs/G1_ACHIEVABLE_CEILING_2026-09-20.md` 的結論：那個 ×1.702 是**故意錯的探針**量到的
**上限**，可交付的倍率取決於**前提 B**（`slot_table` 的發布是否在熱路徑上），而前提 B
**從未被量過**、需要的儀器還沒寫。⇒ **第 2 節那兩列都是「如果」。**

## 4. 這份文件**不能**支持的

1. ❌「我們現在是 13.6 t/s」當成 G7 的正式讀數 —— 官方儀器是 `prod_matrix.py`（llama-bench, 兩軸），
   而 13.6 是從**一次 run 的 (mean_len, step) 配對**算出來的。它是一個**結構正確的估計**，
   不是那台儀器的讀數。
2. ❌「12.62 → 13.6 是進步」—— 兩者不同儀器、不同配置，`MTP_ABBA_RECHECK` §5 已經示範過這種比較
   會落在噪音裡。
3. ❌「G6 已 met」—— 見 §2.1，`from` 的可比性未裁決，判決權在 line S。
4. ❌「G1 給 23.2 t/s」—— 那是把**另一個 regime 量到的比率**乘上**這個 regime 的 step**，
   第 2 節的表格標題已經寫明是「按比例套上去」的假設。
