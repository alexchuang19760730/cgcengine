一句話假設

用下一层 router 的真实权重对当前层 attn_post_norm 打分取 top-8，在当前层 GPU 计算时把预测专家从 SSD 预取进 pool—— 若命中率对齐上游 >80% 且 I/O 与计算重叠≈0，decode 的 SSD miss 串行等待应被显著压缩； 预测只指导预取、不参与路由，输出逐字节一致。

為什麼這次不同（不在舊判死範圍）

已判死（勿重做）：「鄰居/啟發式背景預取」——用历史频率、层间相关性启发式猜专家，无真实打分依据。
本方案是目標-router 預取：直接拿目标层 router 的权重（ffn_gate_inp）对当前层真实特征做一次 GEMV 打分，argsort top-k。 上游实测命中率 >80%（8 个中约 6–7 个提前驻留），且预测-执行解耦保证逐字节无损。属不同信号强度的方案，需要重新立项验证。

子目標（可量化、可累加，每步帶實測貢獻）

離線命中率復現（不動引擎，最便宜）
dump 每層 attn_post_norm 與下一層 gate 權重，離線重算 top-8 預測對真實路由的命中率；分層曲線 + 首末層標記。
通過：整體命中率 ≥80%（對齊上游），且在我們的 prompt 集（編碼/對話/數學）上穩定。
否證：<60% 或分層塌方（首/末層）→ 方案關閉，不進 G2。
產物：命中率分層圖 + 數據 csv；零引擎改動。
圖內預測構圖移植（默認 off，只預測不讀盤）
對照 qwen35moe.cpp:455-466，在我們 fork 的 MoE 圖加 next-router × attn_post_norm 的 argsort top-k（僅 n_tokens==1）； 先以 READ=0 模式只統計 n_hits/n_armed。
通過：在線命中率與 G1 離線一致（±1%）；預測開/關 decode t/s 差異 <2%（開銷被 hide）。
否證：預測 GEMV 本身造成可測量延遲 → 需降頻或改預測位置。
預取 worker + ping-pong 窗口（重疊 I/O）
移植 lookahead_expert_prefetch：後台 preadv 寫共享 bank 尾部、與當前層 Metal compute 重疊； 埋點 n_hits/n_armed/n_waits/n_wait_ns/n_pred_read/n_pred_published。
通過：開/關預取逐 token logits bit-exact；n_wait_ns 顯著下降；預取深度=8 在一層 compute 窗口內可完成。
否證：窗口內讀不完 8 個專家（我們專家 1.07 MiB × 8 ≈ 8.6 MiB vs SSD 實測帶寬）→ 降 depth 或收斂為「預測指導淘汰」輕量模式。
與 8GB pool / LRU / SpAc / P0-P2 協同
統一窗口模式 + 預測保護淘汰（對應上游 n_evict_saved）；churn 不回升；熱專家不被預取流量踢走。
通過：ABBA（warm-skip64、prod-new）decode 相對 13.722 baseline ≥+5% 且無損、swap 不增、命中率/淘汰計數自證。
否證：收益 <5% 或 churn/swap 變差 → 回退為只預測不讀盤的淘汰保護模式。
MTP 疊加驗證
上游預測構圖僅在單 token decode 生效；驗證 MTP verify 多 token 路徑下的行為（禁用或擴展）。
通過：MTP-on/off 兩檔均不崩、不退化；明確記錄預測在 verify 段的語義。
G6 · LES × 4/6 GiB 縮池轉正（前置 G3/G4 已過）—— 把常駐需求降級為及時預取
背景：8 GiB 池 143 槽/層、缺 113，但每步只補 ~1.8 個（寬鬆 63 倍）⇒ 池沒被填滿、瓶頸是預取品質而非容量；10 GiB 擴池 Metal OOM。 純縮池（4/6 GiB）過去因預取訊號差、新增 miss 補不回而變慢；記憶中 8/6/4G＝12.06/10.48/7.67 已被查證為轉述、不可引用（全語料僅 2 筆 4G、6G 無一手；poolsweep p4–p7 被 cell contract 拒跑）。 G6 用同一 LES 預取補小池新增 miss：矩陣 off/on × 池 {8,6,4} GiB，每池一格（8G=8589934592 / 6G=6442450944 / 4G=4294967296），先以 off 臂重建權威一手 8/6/4 基線。 定義縮池懲罰 pen(x,P)=1−t/s(x,P)/t/s(x,8G)。
通過：6G+on ≥ 8G+off×0.95（小池+準預取追平大池無預取）且物理峰值降 ≥1.5 GiB；4G+on 的 pen 收窄 ≥50%（或 ≥8G+off×0.90 且不超訂）；n_wait_ns 不隨池縮小上升、n_hits/n_pred_read 上升（預取補容量缺口）、swap/churn 不惡化、bit-exact。對應常駐收縮 8→6G＝−25%、8→4G＝−50%（對齊 e-union-cache-shrink 挑戰檔，但不依賴 MTP）。
否證：t/s 隨池縮小同步掉、n_wait 同步升、n_hits 不上升 ⇒ SSD 帶寬/預取深度撐不起小池，縮池軸封閉、保留 8G；僅 6G 過則收縮上限登記 −25%。
線索（未落盤一手 json、須重測核對，不作基線）：operator 回報 4G miss 增 1.91× 而 t/s 10.28→10.60 反略升。

實驗設置硬約束（生產級，charter gate）

  • 唯一入口：harness bench / commit_bench，profile = prod-new；禁止直跑 matrix。
  • --warm-skip 64 熱穩態口徑；固定 seed；ABBA 成對；每臂 reps ≥3。
  • 總開關環境變量默認 off（對齊上游）：LLAMA_MOE_LOOKAHEAD_PREFETCH=1、..._DEPTH（默認 8）、LLAMA_MOE_PREFETCH_READ（0=只預測）。
  • 產物自證欄位：warm_skip_applied、fixed_fill_seed、engine_md5、swap before/after、thermal state、預測命中率與等待計數。
  • G6 縮池矩陣每池一格（池位元組寫進該格測試卡權威 block，避免 poolsweep 單格配臂被 cell contract fail-closed）；每池出完整 json，記錄物理峰值（wired）/swap_growth/churn。
  • 跑前檢查 swap=0 / thermal=nominal；未立項（無 charter）不得開跑。
