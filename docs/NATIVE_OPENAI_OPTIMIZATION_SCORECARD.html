怎麼打分

原則很簡單：每一軸都用 0-100 打分，80 是可接受的收口線，100 是量產就緒或接近量產的狀態。

  • 80 分：這一軸已經足夠支撐後續優化，不再是主阻塞。
  • 60-79 分：方向對了，但還有明顯缺口或覆蓋不夠。
  • < 60 分：這一軸仍是紅區，優先補短板。

API Messages 100

當前技術指標： 6 類 probes 已外部化成 versioned contract fixture

為什麼是這個分數： 目前已把短 QA / 摘要 / strict completion / continuation / code / tool 六類 probes 全部固化進 versioned contract，schema 與回放樣本都已固定。

打分標準

  • 100 = 短 QA / 摘要 / strict completion / continuation / code / tool 六類 probe 都有 versioned fixture，schema 穩定且可回放
  • 80 = 至少短 QA / 摘要 / strict completion 三類 core probes 已 versioned，role/content 邊界固定
  • 60 = 只有部分 probes 有 fixture，仍存在隱含規則或臨時欄位
  • 40 = 主要靠人工描述，沒有固定回放樣本
  • 0 = 沒有 API message contract

Serializer Output 92

當前技術指標： 6 個 contract cases 全部與 native healthy prompt 對齊

為什麼是這個分數： 主線已切到外部化的 last-user policy，最新 contract report 顯示 6 個 cases 全部對齊 native healthy prompt，且不再把 QA system scaffold 硬拼回 prompt。

打分標準

  • 100 = 所有 core probes 的 serializer output 都與 contract 預期一致，且不引入非必要 scaffold
  • 80 = serializer deterministic，所有 gap 都是顯式且被允許的
  • 60 = serializer deterministic，但仍有 core case 會引入不必要 scaffold
  • 40 = serializer 邏輯不穩定，same input 可能產生不同 prompt
  • 0 = serializer 邏輯混亂或回流 prompt intelligence
