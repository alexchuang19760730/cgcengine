## 0. 一句話

**prebind 判活：`qu2`／`qu3` 通過門檻，`qu1` 邊緣。** 但它不是「復活成首選」，
而是與 **ρ** 互補——兩者卡在不同的軸上，且在 cb 定讞（cb=42.04）後的定價**幾乎同價**。

## 1. 為什麼第一版 FAIL 不算數（儀器 bug）

2026-09-23 13:31 那輪得到的結論是「`q24 = 0.354` ⇒ FAIL，結案不做」。該結論**已被撤回**：

- 探針只存了 `ids[0..k−1]`，也就是 **token 0 那一行**；
- 但 MTP decode 一步的 `ntok=4` 是 **4 個不同位置**的待驗證 token，而相鄰兩個 step 的 token
  **完全不相交** ⇒ 「上一步的 token 0」其實是**另一個 token**；
- 因此 0.354 量到的是另一個 token 的路由。

同輪發現的根因也一併作廢：原文寫的「union 有 19.41 個專家、一次只能預測 8 個 ⇒ 覆蓋率天花板
41%」同屬 bug 產物（那個 8 就是 token-0-only 的假寬度）。

⇒ **不要再把「prebind 結案＝不做」當成歷史結論引用。** 那是 bug，不是判決。

## 3. ★ cb 定讞後，原表的兩欄要撤回

`docs/PREBIND_STAGE0_RESULT_2026-09-23.md` 的定價表同時列了 `cb=42.04` 與 `cb=74.18`。
按 `docs/CB_DELIVERY_SETTLED_2026-09-23.md`（2026-09-23 18:0x）的裁定：

> **42 與 74 不是兩個 regime，是同一支 run 的兩個窗口。** `74.18` 只出現在「含池預熱」
> 或「高 swap」那一格；交付錨點用 `--warm-skip 64`（時鐘從預熱後才開始）
> ⇒ **74.18 撤回，交付 cb = 42~51 ms。**

⇒ 該表的 **cb=74.18 兩欄（+視窗 1.30 / 1.59）應停止引用**。同 regime 下只剩：

| 方案 | cb=42.04（同 regime，可引用） |
|---|---:|
| ρ | 14.36 t/s（+14.2%） |
| prebind qu3 | **14.33 t/s（+14.0%）** |

⚠ **`MEMORY.md` 裡「prebind qu3 14.33~16.06」的上界 16.06 只出現在 cb=74.18 欄**
⇒ 隨該欄撤回，**應改寫為 ≈14.33（cb=42.04）**。
⚠ 交付 cb 的 mean 口徑（50.33／51.50 ms）**沒有**被回填進 prebind 這張表 ⇒
「cb=50.40 時的 prebind 收益」是**未重算的空白**，不是已知的 +19%。
（x ρ 那一側已經用 cb=50.40 定價過；prebind 這一側沒有。）

## 4. 與 ρ 的關係：互補，且在 cb=42.04 下同價

兩個方向卡在**不同的軸**上：

- **ρ（提前一層的影子 router）**：覆蓋高（0.849）、過度抓取低（1.03×），
  但**視窗只有 1.30~1.59 ms**（MoE core 佔 segment 60.1% ⇒ 最早只能在 60% 處發起），
  而每層 fill 是 1.05~1.86 ms ⇒ **視窗是瓶頸**；還要付 **4.76 ms/步** 的 GPU 插入成本。
- **prebind（跨 step 的歷史 union）**：覆蓋較低（0.59~0.73）、過度抓取高（1.22~1.48×），
  但**提前一整步發起 ⇒ 視窗 ≈ 一步（~248 ms）**，完全不受限，而且**不插任何 GPU 節點**。

⇒ **選哪個不由方向決定，由兩個未閉合口徑決定**（cb 42 vs 74、視窗 1.30 vs 1.59）。
⇒ 順序是 **cb 先、視窗後**：cb=42.04 時每層需求 1.051 ms < 最悲觀視窗 1.30 ⇒ 視窗根本綁不住。

⚠ 關於「疊加」：不要把 +33% 當成兩個機制相加。那個格點同時取了 cb=74.18（跨 regime 借的）
＋視窗 1.59（未實測）；換回 cb=42.04 ⇒ **14.50**。「疊加」相對「只做 ρ」的邊際價值在所有
實測格點上只有 **+0.03~+0.30 t/s**，低於可負擔的解析度。
完整重算見 `docs/STACK_UPPER_BOUND_2026-09-23.md` 與 `scripts/check/window_joint_ev.py`。

## 5. 沒被定價的成本（仍空白）

影子 ensure 的時間 `shadow_cost` 說 w=28 時 44 ms/步，塞得進 129.8 ms 的陰影窗
⇒ **時間不是瓶頸**。真正沒被定價的是：

1. **LRU 擾動** —— 影子抓取把熱專家擠出去；
2. **多餘 pread 的頻寬爭用**。

兩者都不在 `shadow_cost` 裡，也不在那一輪實測裡。ρ 與 prebind 共用這兩個空白。
