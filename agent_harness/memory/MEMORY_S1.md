## 現行結論

1. **兩臂不是 bit-identical**：錨 `2d4e5099` vs S1 `f0acf7d2`（各四輪穩定）。`sample` 欄：錨
   「巴黎是法国首都…」vs S1「巴黎并非法国的首都…」⇒ 分歧在**第 1～2 個生成 token**。
2. **分歧＝第一個被 GPU table 服務的層的 MoE gather**（r10/r11：該層 router logits 與 top-k 權重逐位元
   相同，而 `gate/up/down/weighted/out` 全 DIFF@1，`sum`＋`xor` **都**不同 ⇒ 不是重排；窗口真值相關係數
   0.16–0.18 ⇒ **互相無關**）。**層號由 `CGC_S1_MIN_IL` 決定**。
3. **已否證的機制（累積）**：額外節點（`p25-keepleaf` 與錨逐位元相同，兩個新讀數也 440/440 SAME）／
   clamp 成 slot 0（`clamped_selected=0`）／對映錯誤（`EQUIV-pool mismatch=0` ×1599）／時序・race
   （`SEL-DRIFT entries=0`）／**slot 反查錯**（`wrong=0`、`owner==ids` 440/440）／**消費者被餵不同 ids**
   （那個 pass 上 120/120 SAME）／**池佈局**（那個 pass 上 40/40 SAME）。**§9.18.4 走完。**
4. **routing 的分岔是後果**：decode 步上兩臂的 ids 摘要各自 440 個互異、交集只有 1；池統計也分岔
   （`miss_capacity` 4648 vs 5349）。但第一個 pool-path pass 上 ids 相同 ⇒ 逐步累積出來的。
5. **設計缺陷（誠實記）**：`wrong=0`＋`unowned=0` ⇒ `owner == ids[j]` ⇒ **SLOT-SEL 的摘要等於 ids 的
   摘要**（`idsum/idsxor/idwsum` 已證相等）⇒ 它量**路由**不是池。**反查在池自洽時是恆等式。**
6. **哨兵**：`p25-keepleaf` ＝ 錨 ✅；**`p25-slotgpu-l20` ＝ `b84eea28` ≠ 錨** ⇒ 09-15「l20 等於錨」在
   當前 build 已不成立 ⇒ 不能當「門檻外」哨兵。
7. **分段陷阱**：段界是 `ffn_moe_gate-1`（段 straddle 兩個 pass）。**池路徑下 `ffn_moe_gate-N` 的 ids 是
   slot 索引，不是專家 id**；GPU table 只給 `il >= CGC_S1_MIN_IL`（預設 1），**layer 0 走 host leaf**。
8. **操作紀律**：**不要讓兩輪 `decode_sweep` 重疊**（搶 8080 與 GPU ⇒ 某臂 `n_rounds=0`，看起來卻像跑過
   了）。判準：`n_rounds ≥ 1` 且 `answer_md5_set` 非空。
