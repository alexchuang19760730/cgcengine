
- **`run_server.sh` 有 env allowlist**：未列出的 `CGC_*` **靜默丟棄** ⇒「沒效果」與「沒設到」同形。新開關
  要同步加 `if [ -n "${VAR:-}" ]; then SERVER_ENV+=(VAR="$VAR"); fi`。
- 索引重生**順序固定**：先 `build_memory_index.py`，再 `index_assets.py`；顛倒 → `--check` 報漂移，而且
  **只重生 manifest 不會修**。**memory 寫完要在索引重生之前。** `index_assets.py` **不要加 `--out`**。
  實際掃描範圍＝`scripts/check/*` ＋ `docs/*` ＋ `agent_harness/engine_loop/*` ＋ `.workbuddy/memory/*.md`；
  **不含 `agent_harness/memory/` 與 `skills/`**（那裡的實體快照是另一條線的手動
  `import_harness_snapshot.py`，要跑就得**先快照、後索引**）。

## 量測衛生

- **md5 只在同 build 指紋 ＋ 同 `predicted_n` 下可比**。每次跑前 `pkill -9 -f llama-server`；交錯 A/B ×3
  ＋配對中位。**`pkill` 對 shell script 需 `-f`，且要驗證真的停了。**
- BSD `grep` 不支援 `\|`（一律 `-E`）；**本 sandbox 的 bash `grep` 會靜默失效 ⇒ 用內建 Grep 工具**；zsh
  `*.log` 無匹配會不執行整條指令；**沒有 `timeout`**；`ps` 被擋、`pgrep` 可用。
- **`CGC-MMID-ASSERT` 的 `id_oob` 不是「消費者讀到什麼」的證據**（encode 期由主機讀 `op->src[2]->data`）
  ⇒ 只能用**內核側**讀數。
- **建置新鮮度的判準是「建置輸出有沒有編譯行」**，不是 exit code／產物存在／mtime。`.metal` 改動另外要驗
  `autogenerated/ggml-metal-embed.s.o` 的 mtime。
- **D5**：`ORACLE_PINNED_ENV` 已釘住（`BATCH/UBATCH=6144`）；重新基線＝`--write-ref` ＋
  `--no-pin-oracle-env`；**先看 `comparable` 再讀 M1/M2/M3**。現行參考檔＝
  `ref_iq3_pool8gb_M2_6144_bitident_v5_spac.jsonl`（與 v4 逐位元相同）。
- **「兩次量測之間只有一個產物不同」≠ 單變數實驗**（前提是**交錯**）。兩候選都無法排除時，正確述句是
  「未歸因」＋指名能裁決它的實驗。
- lesson schema：`superseded_by` 必填（可 null）、`applies_to` 每項是**檔案路徑**。
