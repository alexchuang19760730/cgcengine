# 在這個 repo 新增一個「觀測入口」而不是一份文件

**核心判準（先問這個，再動手）**：這個入口顯示的綠燈，是**剛剛跑出來的**，還是**宣告的**？
宣告的綠燈與沒有綠燈在讀者面前同形 —— 本 repo 的提交閘門自己就有這個陷阱
（不帶 `BIN_DIR` ⇒ 11 段全部 SKIP，卻仍然印 `OK`，見 `scripts/check_build_tracked.sh:688-696`）。

## 四條硬規矩（每一條都對應一個已付過的學費）

1. **單一真相來源**。清單只在一個 JSON 裡。入口顯示的「復現指令」與入口自己跑的是同一份 ⇒
   不存在「文件寫的指令已不是實際跑的那條」。**兩份清單必然漂移**，而漂移是靜默的。
2. **不假裝**。需要 GPU／build 產物／docker／模型端點的檢查，標成 `cost=heavy` 並在前端
   顯示 `SKIP` ＋前題，**不畫成綠燈**。跑不動的綠燈比紅燈更貴。
3. **缺席要出聲**。沿用 `agent_harness/CONVENTIONS.md:7-14` 的驗收形式：每一個節點要嘛有
   **可解析的指針**，要嘛有一行**顯式標記**說明證據形態。指針用
   `{"path": ..., "contains": "<子串>"}` —— 它對行號漂移免疫，純 `path` 不然。
   缺口不是「沒有檔案」，是**沉默**。
4. **可執行檔而不是形容詞**。每一個主張都要能指到一個可重跑的指令；趨勢要落在
   **只追加**的 jsonl，不是落在 HTML 的時間戳。

### ★ 第五條（2026-09-18 新增）：完整性檢查要釘「缺席」而不是「有值」

> 標題的「四條」指的是原本那四條；第五條是後加的。**不要為了數字好看去改標題** ——
> 白皮書 §2 引用的就是「四條硬規矩」，改了會讓那份已提交的文件變成假話。

**規矩**：任何**衍生**的表（表是從某個來源集合算出來的）都要有一條檢查：
**來源集合裡的每一筆都必須在表上有一列；少一列就紅，並指名那一筆。**

實例（`agent_harness/portal/targets.json` 的 `targets_problems()`，2026-09-18）：
綁定表要把 68 筆決策逐筆掛到 prefill 250／decode 25 兩個目標上。加檢查之前，
一筆新決策會**靜默地不在任何目標上** —— 入口看起來完全正常（表上少一列，**人不會去數**）。
加上「每一筆 decision 都要有一列」之後，它當場抓到兩個真缺陷（`momentum.classes` 少一個鍵；
我自己在 `goals.json` 的 `evidence` 裡塞了裸字串）。

**為什麼它與第三條不同**：第三條管的是「**節點**有沒有交代自己的證據」（一對一的義務）；
第五條管的是「**來源集合到衍生表的覆蓋率**」（集合到集合）。前者漏一個節點，那個節點自己會沉默；
後者漏一筆，**表上完全看不出來**。兩者都是「缺口是沉默」，但沉默的位置不同。

**怎麼寫**：閘門不必新開一條 —— 把 `xxx_problems()` 接進既有的 `portal-integrity`
（它跑 `build_portal.py --check`）就是「零新閘門、零索引漂移」的作法。檢查要有兩個方向：
**多了**（binding 指到不存在的資產）與**少了**（來源有一筆但沒有列），只驗一個方向等於沒驗。

### ★ 第六條（2026-09-18 新增）：探測要驗「身分」，不只驗「可達」

**可達 ≠ 是我們的服務。** 只驗 HTTP 200 的探測器會對著**別的服務**報 LIVE，
而症狀**完全像「一切正常」** —— 這是観測器最貴的一種說謊：紅燈還有人會去看，假綠燈没有人會。

**實例（2026-09-18，PowerAuto Portal）**：port 8080 上當時是**另一個 repo 的 llama-server**
（同一個 OpenAI 相容介面，但沒有我們自己加的 `/v1/cgc/profile` ⇒ 回 404）。
舊探測只看 `GET /v1/models` 是否 200 ⇒ 報 **LIVE**，而那個埠上其實**不是我們的東西**。

**怎麼寫**：把身分做成**宣告式**，放在端點註冊表裡：

```json
"identity": {"path": "/v1/edge/status", "object": "powerauto.edge.status", "endpoint_id": "edge-local"}
```

探測流程＝**先驗可達（health path）、再驗身分（identity path 的 `object` 與 `endpoint_id`）**。
狀態要**四分**，不要二分：

| 狀態 | 意義 |
|---|---|
| `live` | 可達，且（有宣告身分時）身分相符 |
| `foreign` | **可達，但那個埠上的東西不是我們的**（HTTP 4xx／`object` 不符／`endpoint_id` 認錯機器） |
| `unverified` | 可達，但身分**驗不了**（探測途中網路錯）—— **不假裝 live** |
| `unknown` | 連不上／非 200 |

兩個必要的細節：
1. **`foreign` 的 detail 要說出「哪個 URL 回了什麼」**，不是只說失敗 ——
   否則讀者分不出「我們的服務掛了」與「別人的服務佔了那個埠」。
2. **沒有宣告身分時要明說「只驗了可達，沒驗它是誰」**，不要讓 `live` 看起來比它實際上更有保證。

**自測的關鍵 fixture**：一個「**假裝是別人服務**」的假服務（同一個 health path 回 200，
identity path 回 404、或回一個不同的 `object`、或 `object` 對但 `endpoint_id` 不對）。
**沒有它，這條最像正常的故障永遠測不到。**

### ★ 第七條（2026-09-18 新增）：產生的文件與漂移檢查（唯一真相只能有一份）

**操作單／清單這類文件，要從註冊表產生，並在 `--check` 裡逐位元組比對。**
否則「改了註冊表但忘了改文件」是**靜默**的 —— 兩份都會被讀，而它們已經不一致。

實作（本 repo 的 `join.json → endpoints/ONBOARDING_<id>.md`）：

- `--gen-onboarding`：從註冊表產生文件（**只寫這幾個檔**，不碰別的）。
- `--check` 重算一次，與磁碟逐位元組比對；不一致就指名「有人手改，或改了註冊表沒重生成」。
- ★ **產生的文件不要放即時狀態**（todo／done 那一類）。放了就隨資料變動，
  於是每次上報都要重生成，漂移檢查會退化成噪音 —— 而噪音會被忽略。
  即時狀態放在**會變的那個地方**（入口頁／匯出）。
- ★ **雙向檢查**：註冊表有但機隊沒註冊（→ 那張單永遠不會被讀）、
  機隊是 offline 但註冊表沒有單（→ 這一端要怎麼進來沒有任何地方寫著）。

### ★ 第八條（2026-09-18 新增）：用角色／權限隱藏內容時，**沉默是最貴的失敗模式**

**預設最小權限是對的決定，但「藏起來卻不說」與「壞了」同形。** 使用者只會看到
「怎麼少了幾區」，然後回報「這一頁應該要顯示 X」。而 X 其實一直都在。

實例（2026-09-18，PowerAuto portal）：預設 `role=user` ⇒ ③ 機台 `display:none`，
使用者回報「https://…/portal/ 應該是要看到本機／windows／鴻蒙端的資產／能力／進度／復盤」。
實測四個維度**全都畫出來了**，只是被藏著而且頁面沒說。

判準：**隱藏時必須在頁面上說出三件事** —— ① 藏了什麼（逐區列名）
② 為什麼（是刻意的權限預設，不是壞掉）③ **怎麼立刻看到**（給可直接點的 URL 或設定方式）。
★ 不要為了「讓使用者看到」就把預設改寬 —— 那會把一個安全決定換成一個便利決定；
   要修的是**沉默**，不是預設值。

### ★ 第九條（2026-09-18 新增）：量「連得到嗎」時，**綁定**與**可達**要分成兩條軸

使用者問「端側在同一個區網上連得到我們的服務嗎」時，第一件事**不是**加通道，
是量**服務綁在哪裡**。這一條補的是前面幾條沒蓋到的那一半。

實測矩陣（macOS，`en0` 192.168.101.90/24；`socket.bind((addr,0))` 之後分別從兩邊連）：

| bind | 從 `127.0.0.1` | 從 LAN 位址 | 應讀成 |
|---|---|---|---|
| `127.0.0.1` | ✓ | ✗ | `loopback-only` |
| `0.0.0.0` | ✓ | ✓ | `bound-lan` |
| `<LAN IP>` | **✗** | ✓ | `bound-lan-only` |

★ 第三列會咬人：**綁在特定 LAN IP 的服務從 loopback 連不上**。
所以「loopback 不通」**不能**推成「那不是我們的服務」—— 第一版把這種判成 `foreign`，
會把一個**合法**綁定誤報成外來服務，而那個症狀看起來像「被別人佔了」。
判定層只有四種（不含 `foreign`）；「**是不是我們的**」是第六條（身分）那條軸。

三件配套：
1. **先量防火牆**，排除最常見的誤判。本機 macOS 應用防火牆是**關的** ⇒ 端側連不上
   **不是**被擋的，唯一的阻礙是「有沒有綁在 LAN 位址上」。不量這一步，
   你會花好幾輪去追一個不存在的防火牆問題。
2. **`--check` 離線、`--probe` 連線**：`--check` 只比對「宣告 vs 原始碼」（純文字，完全不連網）；
   實測綁定放 `--probe`。判準：**宣告說 `lan_ready` 而原始碼其實綁 loopback ⇒ 紅**
   （陳述不實是紅）；**服務沒在跑 ⇒ `absent`，不是紅**。
3. **「綁到區網卻沒有認證」要能出聲**：若服務的身分端點會回 `auth_required`，讀它**當下的**值
   （比宣告準）⇒ 同一份設定，不給 key 就報、給 key 就消失。這是可機檢的紅，
   而不是文件上的一句「請記得加認證」。

★★ **一個會讓這一整條靜默失效的環境變數：`HTTP_PROXY`。**
環境裡若有 `HTTP_PROXY=http://127.0.0.1:7897`（本機實測就是），`urllib` 會把
`http://192.168.101.90:…` **也丟進代理** ⇒ 身分檢查失敗，而判定是 `unverified`（**不是紅**）⇒ **低報**。
修法：`urllib.request.build_opener(urllib.request.ProxyHandler({}))`，並加一格
「環境有 proxy 時仍要 match」。**任何對 LAN／localhost 的 HTTP 探測都要繞代理。**

邊界（要寫在頁面上，不只寫在文件裡）：這些檢查證明的是「socket 綁在哪裡」，
**不是**「別的機器連得到」—— 後者還看 AP isolation／路由器 ACL，只有**對端自己回報**才算數。

### ★ 編輯註冊表時：JSON round-trip 會把整檔重排（2026-09-18 實例）

`fleet.json` 用**單行緊湊陣列**（`"required": ["a", "b"]`），而 `json.dumps` 會把它們展開
⇒ 「讀進來、加一個鍵、寫回去」造成 **223 行**假改動（diff 沒人讀得懂）。

判準（兩條，任選）：

1. **斷言「移除你新增的鍵之後，字串與原件逐位元組相同」**，不符就停手。
   本輪真的靠這條擋下了一次整檔改寫。（但注意：**斷言要在寫檔之前**，
   我第一次寫在 `write_text` 之後 —— 擋下了「繼續往下做」，卻沒擋下那次寫入。）
2. **把新資料放另一個檔**（`join.json`），兩份檔互相交叉檢查 —— 本輪最後採這條：
   新檔沒有格式包袱，而「機器有誰」與「沒進來的怎麼進來」本來就是兩件事。

### ★ 兩個同族的小陷阱（2026-09-18）

- **「N 個分頁」這類描述會在新增分頁時變成假話。** 那一輪加了第五個分頁，而
  `verify_output()` 的錨點清單、docstring、`--self-test` 的 case 名、CLI 的輸出句
  **四處都寫著「四個」** ⇒ 一起改，否則入口會對自己說謊。判準：**新增／刪除任何「被數過的東西」時，
  搜那個數字**（`grep -c '四個'` 之類）比記性可靠。
- **連網那一軸的失敗只能是 `unknown`，不能是紅。** 入口要顯示「跨機」（在版控裡 ＋ 已推到遠端）時，
  第二個條件要連網：本機在中國大陸，而 repo 的其中一個 remote 是
  `https://github.com/ggml-org/llama.cpp` ⇒ 實測 `ls-remote` **75 秒後 timeout**。
  所以：**帶 timeout**、失敗寫 `pushed=unknown`、而且 `--check`（閘門跑的那條）**完全不連網**。
  **一個會因為連不上 GitHub 而變紅的閘門，會在每一個離線的早晨說謊。**

## 入口的四種模式與 rc 契約

照 `agent_harness/portal/build_portal.py` 抄：

| 模式 | 契約 |
|---|---|
| `--check` | 只驗註冊表與指針，**不寫任何檔**；有問題 ⇒ rc=1 且逐條指名 |
| `--self-test` | 黑箱自測（見下）；全過 rc=0 |
| `--gates-only` | 實跑快速閘門並印表；**任何紅燈 ⇒ rc=1**（可進 CI／automation） |
| `--no-gates` | 離線模式；此時**不得有任何 PASS**（不跑就不准宣稱綠） |

`--check` 的「不寫任何檔」要**用 mtime_ns 快照驗**，不是靠讀程式碼相信（見自測 I 格）。

## 突變式自測要涵蓋的東西

單獨寫「乾淨輸入 ⇒ rc=0」等於沒測。至少要這些（`portal --self-test` 有 **18 格**可抄；
2026-09-18 之前是 15，那三格 P/Q/R 就是「釘缺席」那條規矩的陰性對照）：

- **懸空指針** ⇒ rc=1 且**指名**那個路徑
- **沉默**（既無指針也無標記）⇒ rc=1 ← 這一格才是規矩 3 的執行者
- **`contains` 子串漂移** ⇒ rc=1
- **狀態與必填欄位不一致**（例：`status=blocked` 但沒有 `blocked_by`）⇒ rc=1
- **註冊表缺欄位**（尤其 `not_proves` —— 只能證不能否證的檢查不是檢查）⇒ rc=1
- **壞 JSON** ⇒ rc=1 且**不是 traceback**
- **`--check` 不寫檔**（跑前後比對 mtime_ns）
- **只追加的檔案真的只追加**（跑兩次 ⇒ 兩行，第二次不覆蓋第一次）
- **`--no-gates` 不得出現 PASS**
- **heavy 不得出現 PASS**
- ★ **來源有一筆但衍生表沒有列** ⇒ rc=1 且**指名那一筆**（規矩 5 的執行者；反向那格是
  「binding 指到不存在的資產 ⇒ rc=1」，兩個方向都要各一格）
- ★ **fixture 必須帶齊所有註冊表**（gates／goals／targets…）。少一個，`--check` 會先抱怨
  「X 不存在」，於是前面那一批格子**全部拿同一個假原因失敗** —— 自測會變成掩蓋真相的東西。
- ★ **自測本身不得有副作用**：子行程一定要吃「指向 fixture 的環境變數」
  （`PA_PORTAL_REPO`）。本目錄的第一版就是忘了傳，於是「跑自測」等於「在真正的 repo
  原地產生一份入口」，而 13 格 fixture **全部通過**。看門狗做法：跑測前後快照真 repo
  相關目錄的 `(mtime_ns, size)`。

**fixture 要合法**：每個 fixture 都要有一份最小但**合法**的註冊表。否則檢查會先抱怨
「註冊表不存在」，讓 A–E 五格全部拿同一個假原因失敗 —— **自測本身變成掩蓋真相的東西**。

## 提交序列（本 repo）

```bash
python3 <entry> --check            # 1. 註冊表與指針
python3 <entry> --self-test        # 2. 突變式自測
python3 <entry> --gates-only       # 3. 實跑；紅燈是可以提交的事實，但要寫進 message
python3 <entry>                    # 4. 產物（先算 HTML 再寫檔，失敗就不留半套）
git status --porcelain -uall       # 5. 確認別條線的檔 → 只 stage 自己那幾筆，絕不用 git add -A
git add <explicit paths> && git diff --cached --name-status
BIN_DIR='src/llama.cpp/build/bin' RUN_REPLAY_BENCH=0 bash scripts/check_build_tracked.sh --repo "$PWD"
RUN_REPLAY_BENCH=0 git commit -F <msg file>
```

推送照 §6.2：`ls-remote` 拿**遠端真實 SHA**（不是 tracking ref）→ `merge-base --is-ancestor` 驗 FF →
推兩個遠端 → 驗 local／origin／cgcengine0907 三處 hash 相同。

D5 的白皮書：本 repo 每次 commit 都要附 `docs/*.html`。判準是「staged 清單有沒有動 `src/`」；
純腳本／文件的 commit，D5 的**數值那一半**不適用，但白皮書那一半**沒有豁免**。

## 動手時的三個具體陷阱

1. **同一個檔案連續多筆 `Edit` 可能回報 success 而根本沒寫進去**（2026-09-17、09-18 各一次）。
   有效做法：寫一支補丁腳本，每個錨點先 `assert s.count(anchor) == 1`，
   **命中數不對就整批不寫入**；或改完立刻 `grep -n` 驗實際內容。
2. **不要用 shell heredoc 寫含 `${...}` 的補丁**（JS 模板字串）—— zsh 會當成參數展開
   （`Bad substitution: esc`）。把補丁腳本**寫成檔案再跑**。
3. **內嵌 JSON 的 HTML 不能直接數標籤**：產生 payload 時會把 `</` 轉義成 `<\/`
   （防 `</script>` 提前結束）⇒ `s.count('</code>')` 天然少一個。要分區數或先還原。
   這一條的代價不是數字錯，是**會變成別人程式碼裡的前提**。

## 反模式（看到就打斷）

- 在入口裡「順手修」紅燈。**觀測器不是修復器**：把紅燈改綠的最小手段就是讓它別再看。
- 為了讓數字好看而把存檔算成現行代碼（`versions/` 3835 檔 / 1.55M 行 ⇒ 一定要單獨成桶並排除）。
- 用「建好自動化」當「它跑過」的證據。驗收是 `automation_runs` 有紀錄。
- 把入口做成分開選單而非單頁：**這一頁的價值在於四件事同時可見**（目標／決策／閘門／資產），
  分開就沒有人會把它們放在一起讀。
