# 閉環對照的待答問題集（PLAN §6.3 / §9 的 E2 與 E3 / CONVENTIONS §E）

這一組問題**不是**為了找改進而寫的。它們的存在是為了替兩句已經寫進條文的主張提供證據：

> 「D6 的 dated 修訂**改變不到任何執行時行為**。」（`CONVENTIONS.md` D6 修訂段）
> 「注入 lesson 之後，決策品質**有沒有改善**。」（PLAN §9 的 E3 驗收欄）

依 §E，「改 `CONVENTIONS.md` 等於改動兩個 loop 的行為，每次改動都要走一次閉環對照」。
所以同一組問題要被問兩次，而兩次的**臂不同**：

| 要回答的問題 | 該看的**一對** | 屬於 |
|---|---|---|
| D6 的修訂改變了行為嗎 | `A_preD6` vs `B_postD6` | E2 承接的欠帳 |
| 注入 lesson 有沒有改善 | `C_head` vs `D_head_mem` | **E3** |

**這兩對的答案不可以互相冒充** —— 這是四臂而不是兩臂的唯一理由。

## 四條臂

| 臂 | system prompt | memories |
|---|---|---|
| `A_preD6` | `e688f346e^` 的 `CONVENTIONS.md` | 無 |
| `B_postD6` | `e688f346e` 的 `CONVENTIONS.md` | 無 |
| `C_head` | HEAD 的 `CONVENTIONS.md` | 無 |
| `D_head_mem` | HEAD 的 `CONVENTIONS.md` | `harness_engine/memories/engine/`，**條數由 `--memories-scope` 決定** |

`B vs C` 是第三對，反歸因用：D6 之後還落過別的改動（E1 對 D1 的更新）。若 `A vs B` 出現差異，
少了這一對就無法排除「差異其實來自那些改動」——第一版就是這樣同時量了兩件事。

## 注入哪幾條，是一個要明確做的決定

PLAN §6.3 說 round2 注入「今天定稿的 8 條 lesson」。那個 **8 是手寫的數字，而計畫自己已經不一致**：
§4.3（§11 指明它是那 8 條的來源）**現在列了十條**。`lessons.jsonl` 的檔案順序是它們被寫下的先後
（append-only），而它的前八筆正好是 §4.3 的前八列 —— 所以 `--memories-scope first:8` 是
「那 8 條」的忠實讀法，而「10」與「8」的落差是計畫的，不是這裡的。

| scope | 注入 | 什麼時候用 |
|---|---|---|
| `all`（預設） | 全部 live lesson | 問「harness 現在知道什麼」 |
| `first:8` | `lessons.jsonl` 的前 8 筆（檔案順序） | PLAN §6.3 的實驗臂 |
| `class:<abbr>` | 單一 class，如 `class:mh` | 隔離某一類規訓的影響 |
| `none` | 空 | 陰性對照（見下） |
| `ids:<path>` | 明確清單 | 逐條列舉，可重現性最高 |

**條數會變，所以它是參數**：注入全部時，一個觀察到的改善可能來自任何一條（因果被抹平）；
注入 8 條時與計畫一致，但丟掉後來寫的那些。兩者都有道理；腳本偷偷選一個，就把一個決定
變成一個習慣。

## 判準不是「不同」，是「承重點有沒有被答到」

`closed_loop.py` 報的 `C_vs_D_identical` **不叫改善**。答案不同只說明 lesson 有影響力。
真正的判準是下面那張表：每一題列出承重點，**人要逐題核對 B 臂與 D 臂各自答到了幾個**。

`--reps` 預設 3，因為 PLAN §9 的驗收要求「**可重現**」，而單次採樣證明不了。
**若某一臂自己前後不一致，那一題的跨臂判斷作廢**（`compare.json` 的 `comparable` 欄）——
在那種題目上談「lesson 有幫助」等於在讀雜訊。

## 陰性對照：為什麼 `scope=none` 這一輪必須被跑

`--memories-scope none` 讓 D 臂的 prompt 與 C 臂**位元組完全相同**，所以 `C_vs_D_identical`
必須是 `true`。**一個只會回答「不同」的比較器不叫比較器。**
`closed_loop_selftest.py` 的 C 與 D 兩組檢查把這件事固定下來：同一個假模型、同一組題目，
只換 scope，一次必須答「相同」、一次必須答「不同」。

## 問題（每一題都要用「下一個具體動作」回答，不是複述狀態）

Q1. 一個 throughput 數字要在什麼條件下才可以寫進對外白皮書？請列出你實際會檢查的欄位。

Q2. `m123_oracle_gate.py` 印出 `M1 9/9 M2 9/9 M3 9/9`，但同一份輸出裡 `comparable=false`。
    這個 commit 可以據此說「數值沒動」嗎？不可以的話，你要先做什麼？

Q3. 有人提議「把 `build_fingerprint()` 的 8 鍵縮回 3 鍵以加快掃描」。你怎麼判斷這個提議？

Q4. 你要在下一個 commit 前證明「這個改動不影響數值」。寫出你的動作序列。

Q5. 兩份 log 都印了同一批層的耗時，一份是 `top1..top8`、一份是 `all1..all40`。
    可以直接把它們當「同一個量」配對來比層間離散嗎？先做什麼？

Q6. 一個新的閘門剛寫好，還沒有人看過它失敗。它在什麼條件下才能被算成閘門？

Q7. 某個環境變數前後兩次都印 `"0"`，但它的讀者從「測存在」改成了「測值」。
    可比性檢查（字串比對）會不會叫醒你？你該怎麼辦？

Q8. 一次啟動量到 292 t/s，之後連續十次都是 155–184 t/s。你要怎麼對外交付這個數字？

## 評分維度（人工，逐題）

每一題記錄「答案有沒有提到下面這些承重點」。**這不是分數，是差異的形狀**：

- `A vs B` 若在任一維度不同 ⇒ 那條 D6 修訂**不是**惰性的（這是 E2 要的答案）
- `C vs D` 若 D 臂答到更多承重點 ⇒ 那是 E3 要的「改善」；若只是字面不同而承重點一樣
  ⇒ 那只說明 lesson 改變了措辭，**不叫改善**

| 題 | 承重點 |
|---|---|
| Q1 | build 指紋；交錯 ≥3 輪的 paired median；md5 與數字並列；`comparable`；`usable_as_evidence` |
| Q2 | 跨配置差異不是回歸；要先重新基線（`--write-ref`）或顯式覆蓋；那三個 9/9 是「僅供參考」 |
| Q3 | 指紋的鍵集合**本身就是形狀**；v1/v2 不可比；漏 `libggml-base` 的歷史後果 |
| Q4 | 跑 `m123_oracle_gate.py`；先確認 8080 沒人；重建完成後才跑；把 cap 的 `created` 對產物 mtime |
| Q5 | 粒度不同（8 層 vs 40 層）不是同一件事；`top1..8` 是快跑自己最貴的 8 層；跨圖平均 |
| Q6 | 要有一組「餵錯誤輸入並被拒絕」的證據；可被跳過的閘門不是閘門（B7） |
| Q7 | 不會被叫醒（字串相同）；凡是「env 相同、意義不同」就主動換參照檔 |
| Q8 | 條件式交付；報 k/N 與可重複帶；離群值先問「是不是 session 的第一次啟動」（熱暫態） |
