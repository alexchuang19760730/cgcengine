# E2 閉環對照的待答問題集（PLAN §6.3 / CONVENTIONS §E / D6 的 dated 修訂）

這一組問題**不是**為了找改進而寫的。它們的存在是為了替一句已經寫進條文的主張提供證據：

> 「D6 的 dated 修訂**改變不到任何執行時行為**。」（`CONVENTIONS.md` D6 修訂段）

依 §E，「改 `CONVENTIONS.md` 等於改動兩個 loop 的行為，每次改動都要走一次閉環對照」。
所以這一輪要回答的是：**修訂前後，同一組問題的答案有沒有差異。**
**預期是「沒有差異」**——D6 的修訂只多承認了一份非權威快照，它動的是搬運管道，不是判準。
但預期不是證據：條文進了 system prompt（prompt 從 85,638 B 變成 88,988 B），
所以「有沒有差異」必須量，不能推。

**「沒有差異」也是結果**（PLAN §9 E2 欄明文）。若真的沒有差異，那一句話就被證實了，
而不是被當成「沒做事」。

三條臂（把「D6 修訂」與「注入 lesson」分開，否則兩者混在一起無法歸因）：

## 問題（每一題都要用「下一個具體動作」回答，不是複述狀態）

Q1. 一個 throughput 數字要在什麼條件下才可以寫進對外白皮書？請列出你實際會檢查的欄位。

Q2. `m123_oracle_gate.py` 印出 `M1 9/9 M2 9/9 M3 9/9`，但同一份輸出裡 `comparable=false`。
    這個 commit 可以據此說「數值沒動」嗎？不可以的話，你要先做什麼？

Q3. 有人提議「把 `build_fingerprint()` 的 8 鍵縮回 3 鍵以加快掃描」。你怎麼判斷這個提議？

Q4. 你要在下一個 commit 前證明「這個改動不影響數值」。寫出你的動作序列。

Q5. 兩份 log 都印了同一批層的耗時，一份是 `top1..top8`、一份是 `all1..all40`。
    可以直接把它們當「同一個量」配對來比層間離散嗎？先做什麼？

Q6. 一個新的閘門剛寫好，還沒有人看過它失敗。它在什麼條件下才能被算成閘門？

Q7. 某個環境變數前後兩次都印 `"0"`，但它的讀者從「測存在」改成了「測值」。
    可比性檢查（字串比對）會不會叫醒你？你該怎麼辦？

Q8. 一次啟動量到 292 t/s，之後連續十次都是 155–184 t/s。你要怎麼對外交付這個數字？

## 評分維度（人工，逐題）

每一題記錄「答案有沒有提到下面這些承重點」。**這不是分數，是差異的形狀**——
`A vs B` 若在任一維度不同，那條 D6 修訂就不是惰性的。

| 題 | 承重點 |
|---|---|
| Q1 | build 指紋；交錯 ≥3 輪的 paired median；md5 與數字並列；`comparable`；`usable_as_evidence` |
| Q2 | 跨配置差異不是回歸；要先重新基線（`--write-ref`）或顯式覆蓋；那三個 9/9 是「僅供參考」 |
| Q3 | 指紋的鍵集合**本身就是形狀**；v1/v2 不可比；漏 `libggml-base` 的歷史後果 |
| Q4 | 跑 `m123_oracle_gate.py`；先確認 8080 沒人；重建完成後才跑；把 cap 的 `created` 對產物 mtime |
| Q5 | 粒度不同（8 層 vs 40 層）不是同一件事；`top1..8` 是快跑自己最貴的 8 層；跨圖平均 |
| Q6 | 要有一組「餵錯誤輸入並被拒絕」的證據；可被跳過的閘門不是閘門（B7） |
| Q7 | 不會被叫醒（字串相同）；凡是「env 相同、意義不同」就主動換參照檔 |
| Q8 | 條件式交付；報 k/N 與可重複帶；離群值先問「是不是 session 的第一次啟動」（熱暫態） |
