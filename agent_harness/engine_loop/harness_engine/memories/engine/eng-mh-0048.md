[engine] A tracked build artifact is a SHARED resource: rebuilding writes to every experiment currently running on that machine, not just to your own tree. A pre-flight check that merely PRINTS the conflict is not a gate -- the check and the act must be in one branch, so that a non-empty result aborts instead of being observed and then ignored. Before any build, gate on BOTH (a) a listener on the harness port and (b) the measurement processes of every other line (the runner script and the sweep), and abort if either is present; and treat 'the binaries are tracked' as the reason this matters -- a build is a commit-shaped act on the machine's shared state even when nothing is written to git.

## 為什麼（because）

Both the llama-server binaries and the library dylibs live under the tracked build tree, and two sessions were driving the same GPU in the same half hour. The pre-flight `lsof -iTCP:8080` was written into the same shell line as the `cmake --build`, printed the other session's listening server, and the build ran anyway -- replacing libggml-metal and libllama underneath a run that had started 54 seconds earlier. The visible consequence is that the other line's A/B ended up spanning two builds, which silently breaks the single-build premise every comparison in this project relies on; the invisible consequence is that the wrong conclusion is indistinguishable from the right one.

## 反例（counterexample_observed）

2026-09-17 11:29:13 (this machine): `lsof -nP -iTCP:8080 -sTCP:LISTEN` printed `llama-ser 25649 ... TCP *:8080 (LISTEN)` and `pgrep -fl llama-server` printed the same process, in the same command whose next statement relinked `libggml-metal.0.19.0.dylib` and `libllama.0.0.279.dylib`. The other line's runner had started at 11:28:19 and its next arm began at 11:29:22 on the new library. Its two earlier attempts had already died with `Insufficient Memory (kIOGPUCommandBufferCallbackErrorOutOfMemory)` at load_model, i.e. under GPU memory pressure from concurrent work rather than from any assertion.
