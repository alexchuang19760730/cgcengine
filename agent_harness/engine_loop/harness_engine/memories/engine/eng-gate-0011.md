[engine] A fix that changes what a config value MEANS while leaving the string unchanged is invisible to a resolved-config comparability check, because that check is a string diff. It will report a plain FAIL that is a category error, not a regression. So: (a) re-baseline deliberately and retire the old reference, and (b) run the PRE-fix value as a control arm first -- it must reproduce the old reference bit-identically, which is simultaneously the proof that the old reference was dumped under the old behaviour and that the predicate change is numerically inert in every other dimension.

## 為什麼（because）

LLAMA_EXPERT_CACHE_L4_SKIP_LAYER0's three readers were switched from a presence test to value semantics on 2026-09-16. Both the pre-fix and post-fix resolved configs contain the literal string "0" (the profile writes =0 either way), so m123_oracle_gate.py's comparability precondition -- which diffs the resolved ENV of reference and fresh dump -- sees ZERO differences and proceeds to a normal verdict. Measured: the control arm (CGC_SERVER_SKIP0=1, i.e. the pre-fix behaviour under the new binary) reproduced ref_iq3_pool8gb_M2_6144_bitident_v3.jsonl bit-identically (M1 9/9, M2 9/9, M3 9/9, full-row fnv1a64 9/9), while the new default (=0, layer 0 pooled) scored M1 4/9 / M2 9/9 / M3 6/9 with cross-tab {same/same: 4, diff/same: 5, diff/diff: 0}. Without the control arm the 4/9 would have been indistinguishable from 'the fix broke something'. This is the opposite failure mode to the CGC_OA_ASYNC round (dec-20260915-2215), where the resolved string itself moved (CGC_OA_ASYNC 0 -> 1) and the gate raised INVALID COMPARISON on its own, waking someone up. Value-semantics changes get no such alarm, so the re-baseline has to be a declared act rather than a detected one.

## 反例（counterexample_observed）

Two runs with byte-identical resolved env strings (LLAMA_EXPERT_CACHE_L4_SKIP_LAYER0=0 in both) that are nonetheless not comparable: one dumped 39 pooled layers, the other 40. The gate's own re-baseline hint ('A cross-config diff is NOT a regression') never fires, because there is no cross-config diff to report.
