[engine] When an instrument snapshots a shared structure once per capture, store one copy per capture -- do not share one copy between captures that are being compared. A shared buffer makes the LAST capture's state the label for every earlier one, which silently deletes exactly the drift the captures were collected to expose, and it does so without any error: every row still prints a plausible value. The cost of per-capture storage is bounded and stateable (here: slot count x captures, arena grown on demand and capped with a printed warning when exhausted); the cost of a shared buffer is an unsupported conclusion. Corollary: if the snapshot cannot be taken (channel absent, arena full, key unparsable), write a distinct 'not annotated' token and make the reader treat it as absence of evidence -- never as an empty snapshot.

## 為什麼（because）

The per-capture design was chosen over the cheaper one-array-per-layer design while writing §9.18.7. The three MoE nodes of one layer (gate/up/down) are captured within microseconds of each other and would all have read the same shared array, so a fill landing between two of them -- drift inside a single layer inside a single pass -- would have printed identically on all three rows. The whole point of capturing at encode time rather than at dump time was to be able to see movement within the step; a shared array would have undone that while looking correct.

## 反例（counterexample_observed）

Design-level, verified only by the fixtures of the time (2026-09-17): the comparator distinguishes `own=none` (not annotated) from `own=[]` (annotated and empty), and the three-state token is what lets a run printed before the column existed ('OWNER CHANNEL ABSENT', every row UNCLASSIFIED) still produce the identical legacy verdict (`SAME=90 DIFF=15 NOT-READ=0`, `FIRST DIFF = graph 31 ffn_moe_down-1.pool`) as the historical run it is compared against.
