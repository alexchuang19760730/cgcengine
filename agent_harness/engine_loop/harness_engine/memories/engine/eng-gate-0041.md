[engine] A name filter with a fixed-size buffer silently drops its own tail, and the drop is invisible from both ends. `CGC_TENSOR_CAPTURE` is copied into a fixed `dst_filter[N]`, so a long comma-separated list is cut MID-NAME: a 23-name request (312 chars) fitted only 19 names against a 256-byte buffer, truncating inside the 20th, and the four lost names included the one node that round existed to read. The second half of the defect is on the consumer side: the analyser listed only the names that appeared, so a name that was dropped by the filter printed as 'nobody asked for this' -- the same shape as a name the producing op never emitted.

## 為什麼（because）

Capability and request are two different facts, and both failure modes look like silence: a truncated filter and an op that was never hooked are indistinguishable unless the instrument prints the EFFECTIVE list it accepted and the consumer prints the names it was asked for but never captured. Fix is two-sided by construction: raise the buffer and warn on truncation at init, print the effective list at startup, and have the analyser emit a 'requested but never captured' block with the three possible causes (filter truncated / name belongs to a VIEW with no kernel / op not hooked).

## 反例（counterexample_observed）

The round was internally consistent and looked like a clean negative result: every node reported `never`, and the same-arm control agreed. It was committed as evidence before the 256-byte buffer was found; the truncation point sat inside `attn_residu`. After raising the buffer to 2048 the same request produced the missing nodes and the verdict changed.
